# Живая переписка и наблюдение за шиной

Документ описывает контракт текущего пакета LIVE/BUS. До завершения его установки рабочая панель остаётся на прежнем транспорте; наличие этого файла или пройденных тестов не подтверждает включение SSE/NATS на сервере.

## Как движутся данные

Переписка: официальный runtime сессии → owner broker → сервер панели → SSE → браузер. Сервер периодически читает ограниченную последнюю часть истории. SSE убирает браузерный опрос истории, но не означает, что вендор предоставляет push или повторное воспроизведение событий.

Отправка сообщения остаётся отдельным HTTP-запросом. Локальная запись появляется сразу и объединяется с серверной по идентификатору. Обрыв SSE не разрешает повторную отправку команды. «Принято» подтверждает приём сообщения, а не завершение задачи.

Наблюдение за шиной: NATS JetStream → единственный наблюдатель owner broker → ограниченный снимок → HTTP API панели → вкладка «Шина». Браузер не соединяется с NATS. Наблюдатель читает события и подтверждает только собственные доставки; задания исполнителей он не забирает и не запускает.

## Что проверять при задержке текста

1. Сверить версию внизу панели с установленным пакетом. Старый frontend и новый broker могут давать понятный отказ вместо работающего потока.
2. В инструментах разработчика браузера проверить GET `/api/session-events`: ожидается открытый ответ `text/event-stream`, `Cache-Control: no-store`, без накопления событий прокси до закрытия запроса. Длительный незавершённый запрос здесь нормален.
3. Если сеть разорвана, интерфейс должен показать восстановление или резервный режим. Резерв использует `/api/session-live-snapshot`; автоматический возврат к старому медленному `/api/session-history` не предусмотрен. Ручное обновление истории остаётся отдельным действием.
4. При 401 нужен действующий вход. При 403 интерфейс прекращает поток; Android использует существующее восстановление через приложение один раз на поколение авторизации. Повторяющийся отказ не должен запускать бесконечную переавторизацию.
5. 429 означает занятый лимит соединений/запросов; 503 — недоступность источника или несовместимость версии. Проверить server/broker health и текущую операцию, а не отправлять сообщение ещё раз.

Неизменившаяся история не порождает новые snapshot-события. Heartbeat поддерживает соединение, но не доказывает свежесть истории или настроек модели. Подпись модели/уровня отражает настроенное состояние с ограниченным сроком свежести; после его истечения интерфейс показывает неизвестное значение.

При смене сессии, разрыве или смене поколения источника черновик и неопределённые отправки сохраняются. Отметка неполной истории требует чтения актуального снимка; восстановление потока само по себе не доказывает получение всей прошлой истории.

## Как читать раздел «Шина»

`disabled` означает, что источник не включён; это не авария чата. `connecting`, `replaying`, `live` и `disconnected` описывают соединение наблюдателя. Устаревший heartbeat не доказывает, что исполнитель остановился. Отсутствие задачи в доступном окне не доказывает, что она никогда не выполнялась.

`completed` — состояние, сообщённое исполнителем, без независимой приёмки качества. PubAck подтверждает доставку брокеру, не выполнение. Неизвестные время постановки и длительность остаются неизвестными. Ограничение хранения и локальное сокращение обзора явно отражаются в coverage.

Включение наблюдения требует отдельной подготовленной серверной конфигурации и прав только на события. Настройка узла, токена и ACL не выполняется открытием вкладки. Проверять реальный пилот можно только после установки пакета и подготовки доступа; синтетический PONG в тестах не заменяет эту приёмку.

## Проверка выпуска и откат

Перед установкой нужны точный проверенный commit, полный CI, подписанный пакет и принятый механизм установки его состава. После установки сверяются версия, контрольные суммы, обе службы, вход, поток через публичный HTTPS, переключение сессий, восстановление после разрыва и реальное событие разрешённого пилота. Проверка браузером на сервере не заменяет приёмку Android с экранной клавиатурой и сворачиванием приложения.

Откат выполняется принятой процедурой подписанного deployment, с сохранением авторизации и данных. Не копировать отдельные Python/JS-файлы между версиями вручную: frontend, broker и установленный состав должны соответствовать одной проверенной поставке.

Точный контракт: [LIVE](dev/2026-10-09-spec-live-stream.md), [BUS](dev/2026-10-09-spec-live-bus.md), [установка](dev/2026-10-09-spec-live-deploy22.md). Статус установки ведётся отдельно в задаче выпуска.

## Граница установки LIVE22

Новый пакет содержит 22 разрешённых файла и подписанный manifest schema4. Перед первым таким выпуском отдельная проверенная операция добавляет закреплённую offline-зависимость и заменяет контроллер установки; в unit брокера добавляется только путь к необязательной конфигурации наблюдателя. Она не меняет учётные данные пользователей или вендоров. Сам файл конфигурации и права NATS эта операция не создаёт. Без конфигурации раздел шины показывает отключённое наблюдение.

Обычные последующие выпуски выполняются прежней командой без аргументов с подписанным полным пакетом. Вручную удалять pending-маркеры или checkpoint нельзя: они определяют допустимое восстановление. Контроллер восстанавливает исторические журналы schema1/2/3, но новые пакеты старого формата не устанавливает. После ошибки проверки нового пакета возможен только доказанный откат до сохранённых файлов; неизвестные изменения сохраняют свидетельства отказа.

Успешное завершение отката не является установленным обновлением. После прерванной отдельной операции повтор может потребовать нового проверенного пакета: оставшиеся checkpoint сохраняются, автоматической очистки нет. Проверка установки включает точный accepted release, все 22 файла, dependency inventory, root receipt, эффективные роли служб и публичный HTTPS. Публикация APK остаётся отдельной штатной процедурой.


## Раздел «Лимиты» — пакет r15

После входа откройте «Лимиты». Подключённый источник — текущий Codex App Server
на узле LLM. Короткий идентификатор аккаунта — отпечаток ответа источника,
а не выбранный профиль авторизации. Процент на полосе означает **остаток**.
«Неизвестно» и «Источник недоступен» не означают исчерпанную подписку.

Окно определяется длительностью API: primary не обязательно пятичасовое.
Для недели показана шкала7дней с маркерами ×1 и выделенным ×2. Ускоренный
маркер — ориентир оператора; фактический сброс рядом остаётся из API. Начало
шкалы расчётное: reset минус длительность окна. После достижения края ×2
остаётся там до нового снимка/окна; автоматическое пополнение не объявляется.

«Получено» — время чтения native API. Снимок обновляется раз в минуту только
на открытой видимой вкладке; в фоне обновления остановлены. Истёкшее окно
не показывает старый процент как текущую квоту. При недоступности источника
проверьте состояние owner broker и версию native runtime; не переавторизуйте
вендора ради раздела. Поддержаны read-схемы0.161.0/0.162.1, правила мутаций
очереди этим разделом не расширяются.

Claude и удалённые узлы пока не подключены. Старый бот-cache без accountId
не присваивается аккаунту. API `/api/limits-overview` доступен только owner,
анонимный запрос возвращает401. Авторизация сайта и APK не меняются.
