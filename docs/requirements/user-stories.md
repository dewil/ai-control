# User stories: пользователи веб-панели

## US-WEB-USERS-01 — выдать ограниченный доступ (Must, M)
Как владелец, хочу создать отдельную запись и разрешить выбранные проекты через YAML, чтобы другой человек работал только с ними.
- [ ] Один владелец, дополнительные администраторы не принимаются.
- [ ] YAML не содержит пароль, hash или TOTP.
- [ ] Пустой список проектов не выдаёт доступ ко всем проектам.
- [ ] Создание записи не перезаписывает существующий enrollment.

## US-WEB-USERS-02 — управлять задачами своих проектов (Must, L)
Как пользователь, хочу видеть вопросы и результаты разрешённых проектов, отвечать и принимать решения.
- [ ] Snapshot не содержит карточки, имена, вопросы, результаты или ошибки чужих задач.
- [ ] Прямой запрос к чужому agent/qid/generation не вызывает trusted writer.
- [ ] Права определяются на сервере, а не project/user полями браузера.
- [ ] Текущие подтверждения, свежий TOTP для reject и проверки stale сохраняются.

## US-WEB-USERS-03 — отозвать доступ (Must, M)
Как владелец, хочу отключить запись или снять project grant, чтобы действующая сессия больше не позволяла соответствующие действия.
- [ ] Revocation действует на следующем запросе.
- [ ] Нельзя использовать ранее выданную карточку для обхода отзыва.
- [ ] Неизвестный или некорректный project mapping не выдаёт права по совпадению имени задачи.
- [ ] Ошибка чтения policy не превращается в unrestricted mode.

## US-WEB-USERS-04 — продолжить работать после обновления (Must, M)
Как существующий владелец, хочу сохранить пароль/TOTP и доступ при установке многопользовательской версии.
- [ ] Оригинальные credential/replay файлы сохраняются.
- [ ] После единственного planned restart можно войти прежними credentials.
- [ ] Reload сохраняет session/CSRF без продления TTL.
- [ ] Обратный переход к проверенному пакету сохраняет owner enrollment и состояние задач.
