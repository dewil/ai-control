## Intent and invariants
INV-SQUEUE-06A: On click show the exact selected text and visible warning: «Будет отправлен показанный текст. Изменения этого сообщения на Mac могут не попасть в отправку». Explicit confirmation captures snapshot_text, queued_submission_id, action_id and expected_turn_id. Later UI refresh/edit cannot silently replace the snapshot. Cancellation by ID may remove a newer edited native version; this is the expressly accepted boundary. No warning checkbox saved globally, no implicit confirmation from queue selection.

INV-SQUEUE-06B: Server obtains fresh positive active-turn proof for same admitted root/thread/context and compares expected_turn_id before native delete. Idle/unknown/stale target gives changed without delete/steer. Native turn/steer additionally carries expectedTurnId; completed/changed target NEVER falls back to successor/turn/start. No model/effort changes. Snapshot text only, max16000chars; non-text native queue item unsupported, no attachment truncation.

INV-SQUEUE-06C: Under per-thread durable action lock, preserve selected snapshot, immutable target ID/clientID/action UUID/context/root and payload digest BEFORE any delete. Action UUID same immutable request replays stored state without new native mutation; different fields rejected. Native delete=true alone authorizes transition to held; deleted=false means changed, no steer; ambiguous deletion stays delivery_unknown, no steer. Never steer first then delete. A concurrent native dispatcher winning delete causes false and no duplicate steer. native delete dispatch lock is relied upon, not Control flock against desktop.

INV-SQUEUE-06D: After confirmed delete=true, durably reserve ONE steer attempt before wire, then turn/steer(threadId,input snapshot,expectedTurnId,clientUserMessageId original validated clientID). Any timeout/crash after reserve is delivery_unknown without automatic retry/requeue/start. A second fresh active-target proof is mandatory after confirmed deletion and before steer attempt reservation/wire; it cannot replace native expectedTurnId. A proven never-wired refusal leaves held; a JSONRPC rejection alone is not generic non-delivery proof. Successful steer ACK sets accepted, does not promise consumed/completed. Exact history proof may promote unknown to accepted; absence never authorizes retry. Late callbacks cannot downgrade state. If pre-delete intent is found after restart, deletion may have occurred: delivery_unknown, no speculative delete/steer.

INV-SQUEUE-06E: Original native row plus Control action receipt are not two pending queues: action payload is recovery data and never automatically dispatched. held/unknown text remains visible via authenticated read for manual recovery; «В черновик» copies the snapshot only, no network action/new UUID until explicit user send. accepted/changed terminal action removes recovery text atomically, retaining digest/idempotency tombstone. A changed result before deletion must not remove native row; target mismatch after confirmed deletion but before wire returns status=held, reason=target_changed and keeps recovery text. Unknown original enqueue receipt must not be replayed/re-added. Where original Control enqueue UUID is known, status reconciliation accounts for transfer held/unknown/accepted rather than reporting a phantom queued row forever. Mac-originated clientIDs are bounded opaque strings, not required Control UUIDs.

INV-SQUEUE-06F: Recovery records owner-local outside Git/sync, owner700/files600/no-symlinks and existing stable-lock/fsync/atomic-write fences. Bound64 retained recovery payloads /4MiB namespace, cap16000Unicodechars each, larger UTF8 file bound explicit (<=128KiB per record). Capacity checked before delete; overflow leaves native row untouched. Do not broaden existing digest-only record validation blindly. No secrets/vendor auth state stored or raw payload logs. Account/context change blocks mutations, never migrates action to another session/account.
