## Результат
На странице сессий один навигационный список вместо трёх видимых списков pinned/participation/project. Desktop>=1024 sidebar с собственной прокруткой и чат рядом. Mobile/tablet<1024 отдельная панель выбора поверх страницы; после выбора сессии закрывается, чат занимает ширину. Перед выбором панель открыта. Из чата открывается кнопкой «Сессии · внимание N». Чат/черновик/прокрутка сохраняются при открытии/закрытии панели.

## Решения после DESIGN review

1. **Фильтр независим от чата.** `navigatorProjectFilter` и generation его запросов не меняют `selectedProject`, `selectedSession`, `selectionGeneration`, URL, history/SSE/models/queue или draft. Поздний ответ B после выбора C игнорируется. Переключение чата происходит только по явному открытию строки или актуальному успешному созданию.
2. **Создание.** Диалог показывает обязательный `createTargetProject` из разрешённых проектов. Конкретный фильтр предзаполняет его; при All требуется явный выбор. Открытие, смена цели и отмена не меняют чат A. Запросы options/create используют выбранный target, старые operation_id/delivery_unknown/configured-provider правила сохраняются. Запросы ограничены отдельным dialog intent epoch и auth/page scope. Если пользователь после отправки выбрал другой чат или закрыл диалог, поздний успех сохраняется как результат операции с явным «Открыть», но не переключает чат сам. Временное присвоение selectedProject ради options запрещено.
3. **Объединение источников.** Fresh текущий overview даёт статус внимания/ready/work и точные question/result targets. Authorized page даёт актуальное имя/vendor; при отсутствии — overview label/vendor; затем сохранённый pin title/vendor с явной отметкой снимка. Page status/pin activity служат только fallback метаданными и не дают ready/question authority. На каждом действии используется актуальная scoped запись, а не сохранённая в snapshot копия targets. Отсутствие строки в partial overview или неполной странице не означает удаление.
4. **Время.** Для начальной сортировки/возраста допустимы только pin.last_activity и overview.result.completed_at (показывать последнее завершение, если это единственная отметка). Берём максимальную подтверждённую отметку этих полей. observed_at/generated_at/as_of/captured_at не являются активностью. Для остальных время неизвестно, сортировка после известных по стабильному key. Статус idle не означает готовый ответ. Вендор не угадывается при отсутствии поля.
5. **Отзыв доступа.** 401/403 и auth/context reset очищают UI union/snapshot/pending/action targets по существующим правилам. Явно недоступный проект удаляет из всех UI caches его metadata и инвалидирует запросы; late response прежней generation не возвращает данные. Явная redaction/недоступность pin identity убирает старые project/sid/title/targets этой привязки, а activity_state unavailable при available=true означает только неизвестную активность. Восстановление после явного отказа требует нового authorized proof. Обычный timeout/partial omission — stale, не выдуманный revoke.
6. **Недоступные закрепления.** Redacted pins сохраняют только server-provided opaque pin_id и «Недоступная сессия», без прежних приватных данных. Они доступны в ★ для действия «Открепить» и не дают открытия чата. Для этих служебных строк key=pin_id; идентифицируемые сессии по-прежнему dedup по project/sid.
7. **Пределы.** До 256 canonical UI entries и 256KiB display metadata суммарно; snapshot/pending хранят только keys. Один активный paged-project request, явная пагинация, никакого обхода всех проектов. Ранее посещённые страницы удерживаются только в этом общем бюджете, не в отдельном растущем store. При превышении сначала вытесняются не отображаемые, не закреплённые и не выбранные записи по давности поступления/key; видимые строки не вытесняются фоновым обновлением. Если весь бюджет занят, новые записи не добавляются, показывается partial/truncated и «Обновить список»; точное число сверх бюджета не выдумывается. Explicit apply пересобирает snapshot из текущих разрешённых источников и освобождает устаревшие записи.
8. **Счётчики.** Считаются по deduplicated актуальным известным записям внутри выбранного проекта. «Внимание» сохраняет r26 predicate (вопросы, разрешения, ошибки), ready/work — прежние предикаты с приоритетом внимания. ★ включает уникальные закреплённые строки и redacted placeholders. Frozen строки, переставшие соответствовать фильтру, показывают текущий статус и отметку «Статус изменился» до explicit apply; заголовок показывает «Есть изменения». «Новые: N» — только retained новые matching keys вне snapshot, без отозванных и дублей. Counts не объявляют полноту при partial.
9. **Когда пересобирать.** Первое открытие и явная смена фильтра/apply создают snapshot. Desktop resize ничего не пересортировывает. Явное повторное открытие мобильной панели может применить накопленные изменения; автоматическое возвращение foreground или SSE не считается открытием. Pin/unpin — явное действие, допустимо пересобрать snapshot после подтверждённого результата; не скрывать неизвестный исход операции.
