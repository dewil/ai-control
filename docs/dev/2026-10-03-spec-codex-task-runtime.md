# CXTASK-RUNTIME — полный dedicated Codex TASK runtime

Дата: 2026-10-03. Base d6744ed. Draft integration root CONTROL-CXTASK. Helper PR не завершает эту задачу: результат — работающая opt-in TASK от создания до ответа человеку, проверки, завершения либо отмены и безопасного архива. Источник поручения — пользователь «делай пока не закончишь»; проектные настройки модели и effort сохраняются.

## Поведение и границы

`claude-rc agent new-task --engine codex --name N --project P --text T` создаёт explicit `engine: codex`, `type: event`, `runtime: drain`, `workspace: worktree` TASK. Telegram `/new --engine codex project text` выбирает тот же creator. Без engine действует прежний Claude путь. Неизвестный engine и Codex с mission/direct/handoff, shared workspace либо несовместимым template отказывают до публикации. Отдельный `task-codex` template задаёт bounded no-shell контракт; Claude ACL, session IDs, модель, pricing и allow tools не переводятся автоматически.

Dedicated native app-server и local V8 принадлежат одной operation и отдельному transient cgroup. Модель читает scoped files, редактирует собственный worktree через native apply_patch, пишет настоящий TASK question через task_ask и предлагает завершение через task_done. Git checkpoint, итоговая интеграция и удаление workspace выполняются trusted runner только после отзыва authority и kernel drain всех известных hosts. Terminal native turn сам по себе не доказывает quiescence.

Этот root соединяет существующие helpers и operation store; не дублирует store implementation или уже принятые схемы. Store spec `2026-10-03-spec-codex-task-operation-store.md` bee22b9 остаётся источником index/publication/reservation/lock контрактов. Runtime передаёт metadata, но не создаёт замену потерянному index и не переписывает lifecycle journals для восстановления разрешения.

## Публичный controller API и CLI

```python
class RuntimeError(Exception): pass
class CodexTaskRuntime:
    def __init__(self, agent_dir, *, state_root, executable, companion_paths,
                 host_budget, adapters=None, clock=time.monotonic): ...
    def static_preflight(self, *, deadline): ...
    def execute(self, event_key, generation, attempt_id, *, deadline): ...
    def reconcile(self, *, deadline): ...
    def revoke_and_drain(self, reason, *, deadline): ...
    def require_drained(self, *, deadline): ...
```

Модуль `bin/_codex_task_runtime.py`. Constructor inert; public inputs plain canonical absolute strings / bounded plain JSON. state_root и resolved release executables задаёт trusted runner, не model/event/environment override. adapters — только Python test seam, не CLI/config/module-name loader; production использует фиксированные stdlib/native adapters. Все публичные ошибки статические, без prompt/config/secrets. Методы возвращают fresh plain JSON. `static_preflight` возвращает `{ready:true,version:"0.160.0",permission_profile:"control_task",release_hashes:{...}}`; это только готовность попробовать bootstrap, не runtime admission. `require_drained` возвращает literal True либо RuntimeError.

`execute` возвращает `{outcome,event_key,operation_id,thread_id,turn_id,reason}`; IDs null только когда native effects не начались. outcome — `ran|asked|done_requested|blocked|unknown|cancelled`. `ran` означает matching native terminal completed, revoked/drained host и успешный trusted checkpoint; это разрешение shared runner завершить этот inbox event, не TASK acceptance. `asked` означает durable pending question, drain и checkpoint; очередь заморожена. `done_requested` означает staged model intent преобразован в настоящий requested done после drain/checkpoint; окончательное acceptance остаётся существующему человеку/reviewer. `blocked` — известный fail-closed отказ до uncertain effect либо pending human approval, `unknown` — uncertain native/send/history/evidence состояние; оба сохраняют event и hold. `cancelled` требует authoritative desired stopped/cancel path и all-host drain; private dirty changes сохраняются до согласованного shared cancel policy.

`reconcile` возвращает `{outcome:"idle|recovered|blocked|unknown",operations:[...],reason}`; никогда не resend turn/start и не запускает новый host. `revoke_and_drain` возвращает `{drained:true,operations:[UUID...]}` только при полном matching registry/kernel evidence; иначе RuntimeError и persistent hold. reason — фиксированный enum `cancel|pause|recovery|ask|done|terminal|timeout|policy|shutdown`.

CLI shim `bin/codex-task-runtime` предоставляет `preflight`, `execute`, `reconcile`, `barrier` с agent path и фиксированным deadline/budget policy; машинный JSON output, обычные exit codes 0 success, 2 отказ/hold. `claude-agent-run` остаётся владельцем inbox FSM, lease, prompts, checkpoints и notifications; после строгого engine dispatch вызывает controller API, а не CLI subprocess изнутри Python. Native dependency использует existing Codex venv/websockets15.0.1 launcher policy. Explicit Codex runner reexec в verified existing venv выполняется до inbox_init, generic recovery и до acquisition executor flock; loop/drain args сохраняются. Нельзя reexec после взятого non-inherited flock. Missing dependency/version visible refusal; Claude Python не меняется. Shim полезен installation/self-check и read-only preflight; напрямую execute без exact live lease отказывает. Никаких user-provided RPC method/config/argv flags.

## Creator, очередь и lease

До final agent publication creator под existing name lock создаёт private staging dirs/locks, Codex template и workspace; вызывает store.initialize для FINAL binding, затем existing control IO публикует codex_state_id и atomic staging rename. Registry-root находится вне agent/worktree/предков, 0700; JSON/locks0600. Runtime constructor никогда initialize. `.lock`, inbox lock и parent name lock существуют до запуска. Stage failure сохраняет orphan index без launch permission; не удаляет чужой UUID.

Shared runner и store читают spec через bounded `yq -o=json -I=0 . <spec.yaml>` с strict JSON/duplicate/nonfinite parsing и pins. Installed mikefarah yq4.53.3 `-c .` не гарантирует JSON и запрещён в новых strict readers. Existing backend default reader на base использует `-c .`: integration исправляет его invocation на explicit JSON output после independent real-default YAML reader semantic RED, без изменения backend permission semantics. Injected test reader не заменяет этот production regression. Shared runner читает spec strict bounded JSON с pins; отсутствие engine — Claude, точное codex — только новый путь, любое другое значение — refusal. Статический release/profile/budget preflight выполняется ДО inbox claim/lease activation. Ошибка не отправляет Claude fallback и не расходует ordinary TASK turn. Затем trusted shared claim публикует generation/attempt/inflight и runtime может сделать bootstrap operation. Bootstrap требует live inflight reservation, поэтому admission не может честно завершаться до claim.

Все callbacks используют actual backend guard плюс store.guard_locked; lock order questions → done → name → control → inbox → store → journal/host. Runtime не держит store lock при повторном control lock, host drain идёт после release callback/send guards. Native events, пришедшие до turn/start response, только queue; dispatcher запускается после authoritative activate точных IDs. Callback/file-read/response send удерживает composed guard до effect/reply. Cancel отзывает inflight FIRST, затем registry, и не зависит от runner PID.

## Admission, bootstrap и persistence

Статический этап проверяет exact release hashes codex/code_mode_host/bwrap/rg из sealed-profile root, actual regular executable identity/UID/mode/path, limits и возможность own cgroup. Сохраняется безопасный bounded release fingerprint; executable replacement до/после запуска отказывает. Host получает optional trusted constructor argv_factory, default прежний host_argv; Codex TASK передаёт фиксированную closure sealed_host_argv(cwd,inherited_disabled_mcp). Factory output bounded plain argv, anchored executable/listen endpoint; это Python seam, не user dotted path и не environment loader. SystemdTaskManager optional trusted constructor memory_max/tasks_max validated positive builtin ints with controller policy minimum/maximum (no bool/negative/unlimited string). Для TASK отсутствие реально applied manager budget отказ; existing default behavior вне TASK сохраняется. Никакого global monkeypatch или system config mutation. `MemoryMax`, `TasksMax`, CPU/runtime deadlines реально применяются native host cgroup, отдельно от agent unit; V8 попадает в тот же cgroup. Account admission включает оба бюджета и не обещает free RAM, занятую inherited daemon.

Каждая operation резервирует store.prepare/launch_guard ДО host start и durable start intent/reserve_start ДО native turn/start. Native transport exclusive, peer socket PID/UID/cgroup и original invocation pinned. Thread start — sealed params с local environment и exact пятью canonical dynamic descriptors. Model/effort не выбираются; persistent thread UUID и native IDs хранятся отдельно от Claude session_id.

Bootstrap имеет фиксированный diagnostic prompt: исполнить только exact `text(ALL_TOOLS.map(t=>t.name).sort())`. Это специальная операция без ordinary TASK prompt и без TASK callback authority. Нужны raw native custom-tool input/output correlation и exact registry из sealed profile; model final text не evidence. Перед любым callback/effect runtime проверяет actual V8 child `/proc` executable identity/hash/current UID и принадлежность pinned native cgroup. Неожиданный tool call, ASK/DONE, approval, file delta, missing registry/raw output либо unknown process — durable revoke/abort/drain и quarantine; изменения не discard. Проверка baseline worktree delta — trusted comparison после drain, не model claim.

Bootstrap terminal + revoked all-host drain позволяет trusted checkpoint/admission receipt. Empty newly started thread ещё не удовлетворяет lifecycle materialized-history prerequisite. После bootstrap runtime подтверждает persistent UUID и terminal native history, только затем создаёт TaskThread/lifecycle для ordinary operation. Admission receipt bound к incarnation, release fingerprint, profile/config digest, exact descriptors, registry and immutable native thread. Продолжение создаёт НОВУЮ operation/host после require_drained всех предыдущих, sealed thread/resume с повторной policy/catalog/history verification. Resume RPC не получает unsupported dynamicTools/environments. Pinned source core/src/session/mod.rs:751–755 при пустом incoming dynamic_tools читает conversation_history.get_dynamic_tools(); protocol/src/protocol.rs:3176 сохраняет SessionMeta.dynamic_tools. Controller читает только первую строку EXACT owned thread.path внутри trusted CODEX_HOME/sessions: bounded <=1MiB strict JSON, UID0600 single-link, no symlink file/parents, canonical root/path и inode/stat pins до/после. Из session_meta извлекаются только id/cwd/cli_version/history_mode/roots/dynamic descriptors; весь header с account/creator/base instructions не сохраняется, не выводится и не передаётся дальше. ID/cwd/version/roots сверяются с operation/thread/release. Descriptor normalization разрешает только omitted deferLoading → False; true/nonnull/malformed/extra descriptor поля отказывают. Canonical пять descriptor schemas должны совпасть с receipt. Persisted header плюс source-backed retention и observed resumed config/environment/history составляют resume evidence; live normal-turn correlated registry snapshot дополнительно подтверждает текущую registry. Не существует придуманного descriptor RPC и никакая model final prose не evidence. Native profile drift/descriptor loss/persistence uncertainty запрещает ordinary send; никакого скрытого thread replacement.

История последовательно используемого persistent thread не заменяет per-operation journals. Stale/uncertain start не повторяется. lifecycle.prepare/submit/reconcile используются с immutable operation ID; event loop получает callbacks непосредственно из runtime transport (observe не должен поглотить их). Native notification alone не завершает operation: требуется reconciled owned turn/history, authority revocation и matching owned cgroup drain. Local V8 yielded cell может жить после terminal: abort/drain обязателен перед git независимо от terminal.

## Tools, вопросы и native human approvals

`task_read/task_search/task_list` используют bounded file helper под composed operation guard. `task_ask` — generic bridge + concrete backend writer создают существующий question JSON с native binding. После первого question controller фиксирует pending outcome, interrupt intent, отзывает operation и abort/drain owned host. Допустим только acknowledgement уже durable intent под тем же live guard; dispatcher сразу закрывает доступ ко всем последующим TASK tools и выполняет bounded interrupt, revoke и abort/drain. ACK не означает разрешения продолжать изменения; native receive/interrupt race проверяется actual E2E. Даже если terminal уже наступил, нужен drain. Затем checkpoint сохраняет changes, shared runner возвращает asked и блокирует очередь до genuine question-file answer. Продолжение передаёт trusted answer из shared resolver; модель не может подделать answer event/body как human authority.

`task_done` НЕ вызывает shared done writer внутри живого model/cell. Runtime под composed active guard durable пишет exact-operation done intent (summary/question arguments + call/RPC IDs), затем interrupt/revoke/drain; trusted checkpoint создаёт clean worktree. Только после all-host gate вызывает существующий request_done_locked под его actual locks и matching still-valid TASK incarnation/generation/desired/acceptance, используя durably staged arguments. Это отдельный trusted continuation, не backend active guard после revoke. Повтор matching staged intent replay не делает второй request; missing/corrupt/conflicting intent hold. Existing writer сохраняет requested-only/ownership-transfer/finalized-false semantics, raw summary escaping ровно в render. Runner finalizes requested done только после matching drain/checkpoint; агент не получает git/commit executor.

Native command/file/permissions/request-user-input callbacks не autoapprove. Pending durable record включает operation/incarnation/generation/attempt/thread/turn, typed RPC ID (0/int и string различны), method/item/call identity, canonical request digest, bounded human choices and status. Используется existing approval question и extra.native_callback с перечисленной identity и payload fingerprint; actual writer принимает только decision approve|reject вместе с answered_at/answered_by. Existing Telegram `p:qid:a/r` маршрутизируется по registered agent/qid. Approval record НЕ использует Claude PreToolUse token. Renderer показывает конкретное действие, root scope, engine Codex; raw native strings escape/cap. Trusted question answer writer единственный источник response decision, ответы model/event payload не принимаются.

Для active waiting approval сохраняется тот же live operation: scheduler не освобождает lease, host budget/timeout продолжает действовать, exclusive waiting controller читает только trusted answer file. Это отличается от task_ask, которое отзывает/drains turn. Heartbeat waiting_input bound к точным incarnation/generation/attempt, фиксированному iteration_start и progress timestamp; human deadline не больше operation deadline, snooze не продлевает authority. Answer envelope потребляется и перемещается done/dedup после verified explicit native reply и закрытия question, не создавая второй turn. Uncertain reply никогда не resend: revoke/drain/quarantine. Transport.receive timeout закрывает соединение, поэтому waiting loop периодически вызывает bounded thread/read, захватывает wire events и дренирует уже имеющийся FIFO; не вызывает receive на пустой очереди и не использует concurrent transport threads. Перед human-derived reply вновь exact backend+store+pending-request guard, pinned V8/host, current question status и fixed baseline policy. Разрешение человека не добавляет network/outside roots/shell/MCP/unknown scopes; acceptForSession, amendments и inherited grant расширения запрещены. Command request при no-shell профиле — policy violation, revoke/quarantine, не human workaround. Unknown callback или unsupported questions/options — blocked/refusal, не guessed answer. File approval params содержат только threadId/turnId/itemId/startedAtMs/reason/grantRoot и не содержат patch; reason и grantRoot сами по себе никогда не доказывают scope. Controller captures native `item/started` fileChange либо matching `item/fileChange/patchUpdated` (source v2/item.rs:330,1140,1528) с exact thread/turn/item correlation, full nonempty changes list <=100 entries/256KiB, bounded regular JSON. Каждая change exact `{path,kind,diff}`, kind Add|Delete|Update с source-schema move_path; update с move проверяет оба paths. Canonical full-changes digest и per-path metadata pins входят в pending approval record. Raw matching apply_patch input может служить supplemental digest evidence, но без independently decoded complete changes не заменяет scope proof. RPC может прибыть раньше item: request queue waiting_correlation, no approval send/question approve option до bounded matching item; missing/duplicate/conflicting/truncated changes → refusal/revoke. Любое patchUpdated изменение после pending publication инвалидирует old approval digest и требует нового question, не исправляет данные под ранее выданным разрешением.

Для accepted baseline approval каждый affected path и move destination каноничен строго внутри own cwd, ancestor chain no symlink, file safety соответствует fixed profile, forbidden secret names/.git и outside paths запрещены даже prospective AddFile. `grantRoot` nonnull означает возможный session grant и не принимается: human может только decline/cancel; acceptForSession запрещён отдельно transport. UI показывает decoded полный список затронутых paths/change kinds и bounded diff preview, не reason-only. Если нет полного correlated patch, controller может показать refusal status, но не approve button. Natural own outside AddFile acceptance fixture проверяет callback delivery и human decline, не outside grant. Resolved/stale/dead/changed-payload RPC нельзя reply, даже если human нажал approve. User input answers сопоставляются captured native question IDs; async model prose/questions остаются untrusted progress и не становятся TASK evidence.

Waiting-controller crash: recovery revokes/drains host; старый approval получает stale/cancelled status. Новая operation может попросить новое подтверждение, но не replay старый live callback. Human approval timeout не autoaccept/auto-default; bounded cancel/revoke/drain, pending UI помечается expired. /pause и /cancel всегда выигрывают до reply за счёт actual fence.

## Recovery, lifecycle, checkpoint и destructive gates

На startup/reconciler сначала validated store snapshot. Каждый known prepared/active host восстанавливается только по immutable journal, invoke/token/PID/cgroup evidence; missing index/partial launch/unknown completeness даёт hold. Новое состояние не initialize, reserved start не retry. inflight/index partial state дожимается только по store monotonic rules; absent runtime process не доказательство остановки. Все known generations/attempt hosts перечисляются и revoke/drain; чужие/shared daemon не затрагиваются.

`require_drained` — единый mandatory barrier перед checkpoint git, done finalize/acceptance, cancel branch handling, worktree removal, archive/name reuse и lease release. Existing shared paths `recovery_pass`, `finalize_worktree_done`, `cmd_done_advance`, `_apply_cancel` и archiver/reconciler должны строго dispatch engine и вызвать barrier для Codex ДО существующего effect, включая direct admin/CLI invocation. Reconciler shutdown выполняет Codex barrier до раннего return lease=None: orphan known host всё равно подлежит отзыву/drain. Unknown/corrupt marker/index блокирует effect и оставляет state reviewable. Нельзя снять hold просто потому, что receipt есть либо unit inactive: нужен полный index и matching original host drain proof.

Git trusted checkpoint использует existing task worktree safety: pinned canonical project/root, branch/base ownership, hooks disabled, bounded subprocess deadline, no model-controlled argv/config/author executable. Dirty changes после failed/unknown/bootstrap violation сохраняются, branch не reset/clean. Cancel сохраняет shared explicit policy, но gate не пропускает живую V8. Checkpoint failure оставляет revoked/drained operation и hold; controller не сообщает ran/done_requested. Lease release после interrupted/failed разрешается только при barrier; failed terminal всё равно не successful event. Lifecycle metadata terminal+quiescent proof записывается после actual drain, store.finish exact matching IDs; callbacks уже revoked.

## Completion intent и crash reconciliation

Единственное durable расположение — `<store operation directory>/completion.json`, current UID0600 regular single-link с pinned private parents, strict bounded JSON<=64KiB/duplicate/nonfinite refusal; completion.lock0600 берётся после composed store fence, не вместо него. Schema exact keys: schema=1, operation_id, task_incarnation hex32, generation, attempt_id, event_key, thread_id, turn_id, request_id typed builtin str|int, call_id, request_digest lowercase sha256, summary bounded raw UTF8, phase, checkpoint, done_receipt. Nullable fields только checkpoint/done_receipt до их фаз. Phase enum requested|revoked|drained|checkpointed|done_written|finalized. Immutable fields совпадают с original captured task_done request и store operation; конфликт не перезаписывается. Summary переносится unchanged в requested done, renderer escaping отдельно. Повтор одинакового intent не даёт второй conversion.

Перед trusted git commit intent под completion fence записывает checkpoint PREPARATION receipt: `{branch,parent_sha,tree_sha,commit_sha:null,trailer}`; branch exact owned task branch, parent/tree SHA40 из trusted Git, trailer `Codex-Task-Operation: <operationUUID>` и отдельный `Codex-Task-Intent: <request_digest>`. Git staged tree/parent проверяются после git add и до commit; unrelated changes не подхватываются между checks. Сразу после commit сверяются actual commit parent/tree/exact trailers и записывается commit_sha. При crash между commit и receipt recovery рассматривает только exact HEAD owned branch, direct parent==prepared parent_sha, tree==prepared tree_sha и оба exact unique trailers. Совпадение позволяет дожать receipt/phase без нового commit; любое расхождение hold, не arbitrary-HEAD acceptance. No-change checkpoint сохраняет exact verified HEAD/tree/no_commit=true с соответствующей explicit receipt variant. Commit argv/policy/hooks/trailers не model-controlled.

После drained phase continuation guard separately берёт questions/done/name/control/inbox/store/completion, сверяет intent/control/incarnation/generation/attempt и registry all-host drained без требования active callback. До shared request_done_locked пишет conversion intent; после writer сохраняет exact done owner event/summary/binding digest receipt и phase done_written. Crash после done write восстанавливается только из matching actual requested/finalized done.json, а не второй writer call с guessed arguments. Финализация существующим finalize path требует этот receipt и drain gate; phase finalized сохраняется только после observed finalized done. Pending cancellation/human acceptance конфликт удерживает blocked и не отменяется completion recovery.

## UI, стоимость, limits и installation
