# Расход и временное окно на общей шкале

Owner CONTROL-WEB-LIMITS-INTEGRATION. Base r15 ae6a763.
Пользователь11.10: график показывает остаток, из-за чего сравнивать расход
с движением окна неудобно. Основная величина — потраченный процент.

INV-WLIM-17: Для доступного неистёкшего окна расход=100−remaining_percent,
главное число явно подписано «Израсходовано». Progressbar показывает расход
от0до100, а остаток — вторичный текст. Unknown/expired не рисуют фиктивный
расход; истощение remaining=0 означает spent100 и прежнее предупреждение.
API/DTO/cache, валютные балансы, auth и фактические resets_at не меняются.

INV-WLIM-18: Для недельного Codex с валидным якорем один общий track
содержит заполнение расхода и оба маркера прошедшего времени×1/×2.
Левая граница0%, правая100%=7дней. Положения времени прежние:
min(7,max(0,elapsed_days)) и min(7,max(0,2*elapsed_days)). Расход от времени
не вычисляется. Видимая шкала7дней и легенда сохраняются. Формы маркеров
различаются, ×2 остаётся главным ориентиром. Для остальных окон обычный
расход без выдуманных маркеров. Это снимок, не исторический временной ряд.

Приёмка: remaining75=>израсходовано25%, полоса25%; elapsed1day=>×1на1/7,
×2на2/7 той же полосы. remaining100=>spent0; remaining0=>spent100 и
исчерпание; unknown/expired=>неизвестно без заполнения. На320/360px
нет горизонтального переполнения, подписи/маркеры видимы и доступность
progressbar/meter отражает расход/время раздельно.
