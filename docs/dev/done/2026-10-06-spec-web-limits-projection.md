## Problem and intended behavior
Existing digest stores one provider section per host snapshot, with no account identity. It must not be relabelled as either of two accounts. Before the panel integration, implement a pure allowlisted projection of already account-bound cached usage records. No probe, token refresh, files, subprocess, environment, networking or authentication is performed by this module. Authenticated caller later supplies expected provider/account from its approved registry. Projection checks equality; it does not attest the collector or grant authority.

Public module bin/_control_web_limits.py exports project_limits(record, *, provider, account_id, now, stale_after=2700). Supported provider codex/claude in this first slice; future vendors require adapters. account_id ASCII [A-Za-z0-9_-]{1,80}. now must be an exact built-in finite int/float (not bool) in [0,253402300799]; stale_after positive int not bool. Invalid caller configuration raises ValueError with fixed generic text, no interpolated input. Record None or malformed/foreign/unbound legacy snapshot returns unavailable view, never a inferred account match or zero remaining. Caller handles authorization; this pure function never reads registry/cache itself.

Record JSON-shaped ordinary built-in dict only; no custom Mapping/proxy/callback adapter. Accepted input: schema integer exactly1; provider/account_id exact expected; captured_at exact built-in finite int/float epoch seconds in [0,253402300799] and <=now; status ok|error|stale|locked|unavailable; plan optional allowlisted exact Free|Plus|Pro|Max|Team|Business|Enterprise, otherwise null; windows built-in dict optional (absent means empty). Unknown keys ignored, never copied to output. This allows collector private metadata without exposing it. Legacy received_at/snapshot dict has no schema/account binding and is unavailable. No fallback from expected account A to account B.

Window keys accepted only five_hour, seven_day, seven_day_opus, seven_day_sonnet in fixed order. Each value ordinary dict with remaining exact built-in finite int/float not bool in [0,100], resets_at optional exact built-in finite int/float epoch seconds in [0,253402300799]. Invalid remaining => null; invalid resets_at => null independently. Unknown/custom window ignored; output at most4. If resets_at exists and <=now, remaining becomes null (window expired, never automatically100/0). Missing reset allows last captured numeric to remain with freshness status. Empty/malformed windows produces empty list without inventing limits. Section status error/stale/locked/unavailable suppresses all window remaining/reset values (empty list); numbers from failed probes are not current usage. status ok with valid captured_at older/equal stale_after becomes stale and retains safe last-known windows with explicit cache age. Age==stale_after is stale. Clock rollback/future record timestamp returns unavailable with captured_at/age null. No state persisted and no max/clamp changes; collector owns its existing clamp semantics.

Exact safe result keys: schema1, provider, account_id, status, plan, captured_at, age_seconds, windows. Each window exact keys id, remaining_percent, resets_at. status ok|stale|error|locked|unavailable. age_seconds=max(0,now-captured_at) finite numeric; unknown cached record has status unavailable, plan/captured_at/age_seconds null and windows[]. For valid non-ok records keep safe captured_at/age/plan and status, windows[]. The output has independent fresh built-in containers; it never returns input nested dict/list objects. No detail/error/reason/email/token/path/raw snapshots/credentials copied. No unsafe string is interpolated in errors, plan is allowlisted and output IDs use validated caller data.

Resource limit: input may contain extra keys, but implementation must not iterate/copy them; only bounded key validation (at most64 keys in top record, windows map and each leaf window dict; larger top maps unavailable, larger windows maps empty windows, malformed/oversized leaf window dicts omitted entirely), exact-key reads and four known window entries. No decoder/JSON serialization, no traversal of unknown metadata. Before any dict get, check exact built-in str keys by bounded iteration; non-string/subclass keys reject that container without hashing/comparing them. Known scalar fields and caller parameters also require exact built-in types before comparisons/regex/arithmetic; bool and scalar subclasses rejected. Arbitrary custom values are rejected/omitted without invoking magic methods. Unknown metadata values never traversed. The timestamp upper bound prevents huge-int/float overflow and corresponds to the last whole epoch second of year9999. Strict built-in dict checks avoid user-defined mapping callbacks. Invalid provider/account/now/stale_after configuration fails before reading record. The function cannot make arbitrary supplied strings safe for downstream HTML: callers render validated identifiers as text, not markup.
