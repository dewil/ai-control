## Proven pause semantics and limits

Actual NATS2.15.0/nats-py2.9.0 proof: `/var/tmp/control-nats-auth-compat-20261013/consumer_pause_proof.py`, secret-free `consumer-pause-result.json`, proof SHA256 `d88f065bb2761947260904f6182f5184ea184e1c8003bde69297eed7ab189f3a`. Sixteen checks PASS using a random synthetic token, ephemeral loopback port and temporary FILE store. No native CLI/executor, live config/credentials/services, ALP, or production ports were touched.

Raw `$JS.API.CONSUMER.PAUSE.<stream>.<consumer>` with `{"pause_until":"<future RFC3339 timestamp>"}` stopped new delivery while permitting an already delivered message's ACK. Undelivered pending remained queued. Consumer INFO exposed prior pause, current `paused` and `config.pause_until`; `num_ack_pending` and ACK floor remained inspectable. SIGHUP and FILE-server restart preserved pause, stream/consumer epochs and ACK sequences. Empty request payload resumed delivery; the remaining message arrived and could be ACKed with sequence continuity. The actual proof used a one-hour future deadline; it did not wait for deadline expiry.

An application ownership check refused resume after another synthetic operator changed `pause_until`, leaving that foreign pause intact. This is **not atomic ownership/CAS**: NATS PAUSE has no owner token or compare-and-swap guard. Exclusive administrative coordination across the interval between inspect and update is a mandatory operational prerequisite. A filesystem lock in one controller cannot exclude a different NATS administrator. If exclusivity or pause identity is uncertain, stop the migration and require operator reconciliation; do not overwrite/resume a foreign pause.

Primary API reference: [NATS API reference](https://github.com/nats-io/nats.docs/blob/master/using-nats/jetstream/nats_api_reference.md); server request/response fields: [jetstream_api.go](https://github.com/nats-io/nats-server/blob/main/server/jetstream_api.go). ## Safe cutover quiescence sequence

1. Disable new Control submissions and publisher. Establish exclusive origin administrative ownership for the migration. Identify exact stream and `dispatcher-codex-ai-dev-1` consumer epochs, current pause state/deadline, delivered/ACK floors, pending counts, and the current ALP runner journal identity. Keep sensitive private receipts outside repository/sync trees.
2. If consumer is already paused by another operation, preserve that pause and abort this automated cutover. Do not adopt it merely because the queue is empty. Record the prior pause state before any mutation.
3. Pause the existing dispatcher consumer until a bounded future deadline that covers the maintenance window with margin. Capture the server-normalized returned deadline and consumer epoch in the private operation receipt. Confirm INFO paused=true with the same deadline/epoch. If publication outcome is unknown, reconcile INFO before retry; never assume pause succeeded.
4. Inspect `num_ack_pending==0`. A pre-pause command may already have reached the runner and may still be ingested/ACKed after pause; ACK remains allowed. Broker ACK pending zero proves only command receipt/ingest progress, not idle executor.
5. Obtain a consistent local ALP journal receipt confirming **accepted=0 and running=0**, bound to the expected journal/runner/workspace identity. Runner ACKs after durable ingest; the paused consumer prevents new command delivery. Thus accepted/running zero must be checked after broker ACK pending zero, and checked again immediately before stop. Unknown journal state is not zero. No prompt/result/log/auth content needs to leave ALP.
6. If busy, unknown, disconnect, epoch drift, near-expiry or a changed foreign pause is observed, **abort without stopping/killing the runner**. Restore only this operation's still-identical pause to its recorded unpaused prior state, after checking exclusivity, consumer epoch and exact server-normalized deadline. A foreign/preexisting pause is never resumed. The proof simulated owned-pause busy-abort cleanup; it did not execute ALP journal checks or a job.
7. Once broker ACK pending and journal accepted/running are zero, stop the identified runner gracefully; verify it stopped and journal is still idle. An ordinary stop must not become permission to kill a running job discovered late. Preserve journal/outbox and pending broker commands. Stream `num_pending` may be nonzero: those commands must remain undelivered during cutover, not be purged or re-created. Existing controller outboxes must be inventoried separately; no newly emitted command may bypass admission stop.
8. Perform the separately reviewed user/password cutover. Verify stream/consumer epochs, ACK floor sequences, queue counts and runner fixed profile; restart the runner with the dedicated identity while consumer remains paused. Reconnect/INFO alone do not establish execution success. Resume only the owned pause after readiness checks and then enable controller admission. Tasks queued before maintenance retain original envelope/task IDs.
9. On rollback preserve the owned pause through the required server restart, restore original runner/server configs and code, and verify preserved journal/stream/consumer/ACK identities before resuming only the owned pause. SIGHUP-only users→token rollback failed identity revocation in the earlier proof; restart remains mandatory. If the bounded pause expires unexpectedly, mark quiescence lost and reconcile actual accepted/running/outbox state before any stop/retry.

Pause authority belongs to the offline migration operator, not runner/web/observer/publisher roles. If a dedicated temporary narrow operator is used, its minimal extra permission is publish `$JS.API.CONSUMER.PAUSE.DEVBUS_V1.dispatcher-codex-ai-dev-1` plus the already specified exact stream/consumer INFO and its reply inbox. The separately preserved legacy offline admin role described below can perform this operation within its established broader authority. Do not add PAUSE to runtime ACLs.
