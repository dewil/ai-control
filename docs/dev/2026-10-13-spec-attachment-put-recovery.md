# Исправление мобильной загрузки и восстановления — r29 / APK0.1.9

Владелец: CONTROL-WEB-ATTACHMENTS, продолжение INV-WATT-08/09/10. Пользователь на реальном устройстве получил пустой ответ при загрузке и неактивную отправку. Причина воспроизведена: OriginPolicy блокировал PUT, хотя web использует его для chunk. Публичный сервер принимает метод и возвращает JSON401 без авторизации; блок находится в WebView.

Контракт: разрешён только same-origin subresource PUT на точный raw path /api/session-attachment-chunk, без redirect/fragment/mainFrame. Другие PUT, foreign origin, фон и отсутствие авторизации сохраняют запрет. GET/POST не расширяются. Нет новых permissions, JS bridges или глобальных сетевых послаблений.

Пустой/неразбираемый ответ или сетевой отказ при chunk показывает понятную русскую ошибку, сохраняя staging ID и блокировку отправки. Никаких автоматических повторов. Явная «Проверить загрузку» сначала обновляет capability, затем читает status и продолжает только подтверждённую стадию; уже принятый chunk повторно не отправляется.

Пользователь дополнительно попросил облегчить шрифт: восстановить компактный footer class (потерян в r28), regular400 подписи/кнопки composer и14px radio label при прежнем native label touch target44px. Размер текста сообщения сохраняется.

Проверки: OriginPolicyUploadBlindTest, test_control_android_upload_chunk_host_blind.py — независимый causal RED перед реализацией; test_control_web_attachment_upload_recovery_browser_red.py — два независимых RED. Android policy34, hostchunk3, chooser23/battery32; build/lint/signature и SOURCE отдельно. Web recovery/radio/attachments11PASS; полный CI на окончательном SHA.
