# Переписка с существующей Codex-сессией: первый срез

## Источник и результат

Владелец: CONTROL-WEB-SESSIONS в клиентском backlog. Пользователь05.10.2026: «для меня сессии сейчас важней»; выбранный сценарий: «Переписка: читать историю и отправлять сообщения в сессию». Источник — решение пользователя, сохранённое в docs/backlog/CONTROL-WEB-SESSIONS.md клиентского проекта. Это первый следующий сценарий после принятой task panel, выше дополнительных пользователей.

US-WSESS-01: с телефона выбрать зарегистрированный проект и существующий Codex thread, прочитать последние сообщения и более старую страницу. US-WSESS-02: отправить текст в тот же полный thread UUID, увидеть подтверждённое принятие либо честную неопределённость и проверить доставку после reload. US-WSESS-03: при известном native ожидании понять, что нужно действие в существующем клиенте; веб не подтверждает запрос за пользователя.

Домен: ../specs/web-sessions.md, INV-WSESS-01..08. Этот документ фиксирует контракт для независимых RED tests до implementation. Завершение спеки не означает завершение или установленную готовность фичи.

## Публичный Python контракт

Новый bin/_control_web_sessions.py: SessionChat(rpc, project_path, project_names, receipt_dir). rpc callable(method,params)->dict; project_path callable(alias)->absoluteRoot; project_names callable()->list aliases. Module не получает credentials и не вызывает shell/произвольные executable. Реальный RPC transport находится у owner broker. Возвращаемые значения JSON-safe dict; безопасные domain errors {error:invalid_request|stale|unavailable}, без raw errors/stderr/payload.

| Метод | Успешный результат |
| --- | --- |
| projects() | {projects:[{name:string}]} |
| list_sessions(project,page=0) | {rows:[{sid:string,title:string,status:string}],has_more:bool} |
| history(project,sid,cursor=None) | {turns:[{id:string,status:string,items:[{id:string,role:user\|assistant,text:string,truncated:bool}]}],next_cursor:string\|null,truncated:bool,recent_sends:[{status:accepted\|delivery_unknown\|rejected,message_id:string,turn_id:string\|null}]} |
| send(project,sid,message_id,text) | {status:accepted\|delivery_unknown\|rejected,message_id:string,turn_id:string\|null} |
| send_status(project,sid,message_id) | тот же receipt result либо {error:stale} для отсутствующего ID |

project — existing registered alias, по existing PROJECT_RE; sid/message_id — полный canonical lowercase UUID, а не short prefix. page — plain integer≥0, не bool; cursor — null либо непустая bounded opaque string. Invalid types/unknown alias/invalid UUID/cursor/text дают invalid_request до mutation. Send text string, непустой после strip, ≤16000 символов; отправляется исходный текст без принудительного strip и без redaction, digest тоже от исходного UTF-8 текста. Redaction применяется при экспорте, не меняет пользовательскую инструкцию агенту. project_names/path data проверяются; upstream failure/unparseable response дают unavailable, не пустой список.

projects проверяет aliases и resolution каждого зарегистрированного root, не раскрывает paths. Session listing переиспользует CodexSessions project pagination/UUID/cwd proof, page size8 и bounded enumeration; rows содержат только согласованные поля. Полный UUID закрепляется server-side. После определения строки выполняется metadata-only thread/read ownership proof для каждой экспортируемой строки; mismatch/corrupt data обозначается безопасной ошибкой, не чужой строкой. Имена проходят redact и ограничиваются500 символами.

Безопасное optional поле needs_native_attention:true допустимо в row/history только при подтверждённом текущем callback для этого thread/connection generation либо authoritative thread status waitingOnApproval/waitingOnUserInput. Значение false не экспортируется как гарантия отсутствия запросов; omission означает отсутствие достоверного знания. Original callback payload не экспортируется. Отметка инвалидируется при resolved, disconnect или turn completion; она не даёт права отвечать на callback.

history/send/send_status каждый заново разрешает project root и вызывает thread/read {threadId:sid,includeTurns:false}, проверяет canonical returned id/cwd. Нет доверия ранее закэшированному списку или browser sid. Несовпадение/исчезновение — stale, некорректный upstream/transport — unavailable. Перед turn/start send вызывает thread/resume {threadId:sid} и проверяет returned thread по тому же proof. Если rebind выявлен до отправки, thread/start не вызывается.

## История и bounded export

FR-WSESS-01 (INV-WSESS-02/03): thread/turns/list params ровно threadId, itemsView:"full", sortDirection:"desc", limit:8 и cursor только когда задан. Response data/turn/items/status/nextCursor валидируются. Next cursor остаётся непрозрачным; invalid/oversized/repeated malformed paging не означает конец. UI разворачивает полученные descending turns для обычного чтения и deduplicates по turn/item ID при refresh; API сохраняет серверный порядок.

Allowlist: userMessage.content с type:text → role:user; agentMessage.text → role:assistant. Текстовые части одного user item соединяются в исходном порядке newline. Нет текстовых частей — item не отображается. clientId используется внутри reconciliation, не экспортируется в history items. Сохраняются id/status; отсутствующий/невалидный required identity не синтезируется. Reasoning, hookPrompt, tools, MCP, raw errors, file paths, attachment URLs и неизвестные типы не становятся сообщением. Для известных неподдержанных вложений UI не обещает полноту всех media.

Каждый экспортируемый текст сначала проходит existing _control_web_broker.SECRET_RE/redact, затем ограничивается8000 Unicode characters. Prefix сохраняется корректным UTF-8; clipped item.truncated=true. Полный encoded JSON history, измеренный в UTF-8 bytes с тем же serializer wire, ≤96*1024. При дополнительном сжатии сохраняется видимый prefix текста и выставляются item.truncated и envelope.truncated; нельзя возвращать усечённую страницу как полную. Envelope.truncated=true также при вынужденном исключении части items/turns из-за бюджета; cursor не переписывается так, чтобы обещать восстановление пропущенного содержимого. UI явно сообщает неполноту. Внешний broker limit128KiB сохраняется; bounded history не является full thread/read(includeTurns:true).

history всегда содержит recent_sends: последние максимум8 receipt metadata выбранного authoritative project/full thread UUID, в порядке от новых к старым; без записей — []. Поля каждой записи ровно status/message_id/turn_id; text/digest/private paths/timestamp не экспортируются. Private receipt namespace и bounded recent index принадлежат конкретной паре project/thread; чтение не сканирует весь архив и не раскрывает записи других проектов/threads. Индекс обновляется durable под тем же namespace lock; отсутствие/повреждение index не превращает старый receipt в новый. Envelope byte budget включает recent_sends. После reload UI из history восстанавливает неизвестные message IDs и предлагает ручную status проверку, не send.

## Отправка и восстановление

FR-WSESS-02 (INV-WSESS-04): После успешного resume/proof отправляется turn/start ровно {threadId:sid,input:[{type:"text",text}],clientUserMessageId:message_id}. Не передавать overrides, включая null/defaults; не проверять remoteControl/status/read как обязательное условие. turn/start может steer текущий активный turn того же thread: accepted означает принятие сообщения. Серверный busy/error сохраняет draft и не инициирует queue, interrupt или автоматический повтор. HTTP409 для rejected, UI не описывает accepted как завершённую работу.

FR-WSESS-03 (INV-WSESS-05/06): Receipt reserve под stable private lock, durable atomic write/fsync до любой возможной turn/start отправки. Ключ дедупликации — canonical registered root + canonical thread UUID + message UUID; alias остаётся UI scope, но два alias одного корня делят защитный receipt; хранится digest исходного UTF-8 текста, project/sid/message_id metadata, стадия/status, timestamp и подтверждённый turn ID, без самого текста. При reserve/write failure turn/start не вызывается. Рестарт с reserved/in-flight записью — delivery_unknown. Ответ turn/start с валидным turn ID → accepted; RPCRejected от turn/start тоже → delivery_unknown, поскольку JSON-RPC error не доказывает отсутствие принятия. Ошибка transport/timeout после возможной отправки, invalid response или неясный outcome → delivery_unknown. Упавшая запись accepted после RPC не позволяет повторный send: уже сохранённый reserve защищает от дубля. Не считать отсутствие ответа подтверждённым rejection.

Повтор same key/same digest возвращает сохранённый result без повторного resume/turn/start, после актуального ownership proof. Same key/different digest invalid_request. Rejected ID тоже не переотправляется; новая явная попытка пользователя имеет новый UUID. Private receipt_dir700, regular files600, no-follow anchored reads/writes/locks, вне /data/git и синкаемых /data. Fixtures используют /var/tmp. Повреждённый/небезопасный receipt/dir fail closed, не новая запись. Retention: автоматическое удаление защитных records запрещено в первом срезе; bounded metadata/tombstones могут позже заменить записи без потери dedup. Лимит storage exhaustion даёт unavailable до отправки. Одна JSON запись не содержит raw text/server error.

send_status сначала выполняет актуальный proof. Отсутствующий receipt — stale; accepted/rejected возвращаются как сохранено. Unknown может свериться с максимум8 страниц thread/turns/list(full,desc,limit8): только userMessage.clientId==message_id в том же thread подтверждает accepted, turn_id берётся из validated enclosing turn. После durable upgrade возвращается accepted. Отсутствие совпадения/предел истории сохраняют unknown. Repeated cursor/corrupt upstream/transport дают unavailable; receipt не понижается и сообщение не отправляется. clientUserMessageId не объявляется server-side idempotency guarantee.

## HTTP, broker и runtime

FR-WSESS-04 (INV-WSESS-01/07): authenticated GET /api/session-projects; GET /api/sessions?project=&page=; GET /api/session-history?project=&sid=&cursor=; POST /api/session-send JSON {project,sid,message_id,text}; GET /api/session-send-status?project=&sid=&message_id=. page default0, cursor optional; остальные fields required. Duplicate query/JSON keys, extra fields и неправильные types отвергаются до backend. Origin/auth/CSRF/body limits сохраняются из web.md. Domain invalid_request→422, stale/rejected→409, unavailable→503; accepted→200; delivery_unknown→503 с полным safe receipt result, чтобы UI не смешивал с rejected. GET status unknown возвращает200 с receipt status. Все session ответы no-store.

Backend extension: session_projects(), session_list(project,page), session_history(project,sid,cursor), session_send(project,sid,message_id,text), session_send_status(project,sid,message_id). RegistryBackend получает additive optional constructor argument sessions=None; без SessionChat session methods дают unavailable, существующие task methods сохраняются. Socket wire fixed ops: session_projects {op}; session_list {op,project,page}; session_history {op,project,sid,cursor}; session_send {op,project,sid,message_id,text}; session_send_status {op,project,sid,message_id}. SocketBackend и owner dispatcher повторяют exact-field/type validation и128KiB limit; project/path/RPC не берутся как произвольная команда клиента. Current task ops сохраняются.

Persistent owner-side RPC transport отдельно от existing observer поддерживает initialize/initialized, один receive loop, bounded waiting requests, notification routing и reconnect generation. Этот срез не отвечает ни на один server request, даже error/unknown: не потребляет native callbacks. Transport может отмечать подтверждённое ожидание native attention для выбранного полного thread; после resolved/turn completion/interrupt/disconnect отметка очищается или становится неизвестной. Не обещать replay pending при reconnect. Runtime использует существующий shared AppServer socket, не второй daemon/worker. Root-owned /opt/ai-control-web/venv обеспечивает Python dependencies owner broker; requirements-web.lock добавляет pinned websockets15.0.1. Owner OAuth/config не копируются ai-panel.

Публичное исключение bin/_control_web_sessions.py: RPCRejected(RuntimeError). Оно означает validated JSON-RPC server error для matching pending request ID/current generation; исключение содержит только safe code/class, без raw message/payload. SessionChat считает RPCRejected и прочие исключения после возможной отправки delivery_unknown; server error не доказывает отсутствие принятия. Malformed error envelope не порождает RPCRejected.

Публичный transport contract в bin/_control_web_sessions.py: InteractiveRPC(socket_path,timeout=25), callable(method,params)->dict, lazy connect и close(). Handshake generated0.160: initialize с clientInfo{name:"ai_control_web",version:"0.1"}, capabilities{experimentalApi:true}, затем initialized notification. Exact method allowlist: initialize, thread/read, thread/list, thread/turns/list, thread/resume, turn/start; остальные запрещены до wire send. Один background receiver на connection, сериализация sends, уникальные client request IDs, максимум64 pending RPC, incoming frame максимум4MiB. Неизвестные response IDs игнорируются; server requests остаются без любых ответов. Connection failure безопасно завершает все pending waiters, инвалидирует runtime attention и не повторяет application requests. Новый вызов может восстановить соединение; turn/start автоматически не повторяется. Ответы сопоставляются только в своей generation. Thread/resume subscription живёт, пока broker connection живо; metadata read не заменяет subscription. Ошибки только sanitized class/code, без raw server message/params; deadlines ограничены timeout. Fake Unix WebSocket server проверяет handshake, responses/interleaving, ignored callbacks, disconnect и отсутствие resend; live server не нужен.

## Телефонный UI и приёмка

FR-WSESS-05 (INV-WSESS-08): отдельный session flow рядом с tasks, project и existing Codex session picker, история и older page, draft/send, сообщения «принято», «доставка неизвестна», «отклонено», «недоступно». Busy/rejected сохраняет draft. Неизвестная доставка предлагает проверить status, не auto resend. Reload использует действующую auth bootstrap; history.required recent_sends восстанавливает последние8 message IDs выбранного thread; неизвестные можно вручную проверить по ID без повторного send. Draft/message ID принадлежат выбранной project/thread паре; session switch не отправляет чужой draft. Text escaping, no browser persistent storage, bounded transient view. Native needs-attention при достоверном знании явно просит действие в существующем клиенте; approval buttons отсутствуют.

При latest refresh/poll UI сохраняет доступ к промежуточным сообщениям: если новая limit8 страница не пересекается с уже загруженными turn IDs, возможный разрыв остаётся доступен через pagination, включая ранее исчерпанный older cursor. Загруженные старые страницы сохраняются в правильном хронологическом порядке без дублей. Нормальное пересекающееся обновление не перематывает older cursor. Поздний history/send/status response не понижает уже подтверждённый accepted/rejected receipt до delivery_unknown/sending; видимый receipt и текущая попытка согласованы, поздний ответ не блокирует новую явную отправку после terminal status.

Критерии: независимые synthetic RED tests для публичного SessionChat, HTTP/broker boundaries и negative privacy/dedup/ownership/UTF-8 bounds; implementation GREEN; distinct-model review и CI; synthetic phone QA; затем отдельно установленная проверка existing authorized thread history/send/status с пользователем. Тесты получают эту спеку, не implementation. INV-WSESS IDs ставятся в проверяющих тестах; покрытие: tests/test_control_web_session_chat_contract.py и tests/test_control_web_session_chat_broker.py; browser evidence ведётся отдельно. Без реальных transcripts/credentials/live RPC в подготовке спеки и unit checks.

## Следующий срез и честные ограничения

Native command/file approvals и user questions — обязательный следующий отдельный корень: token identity, payload digest, connection generation, explicit one-off accept/decline/cancel, stale/cross-thread/resolved guards и необходимые данные действия. Нынешний срез не даёт ответить на них с телефона и может ждать existing client. grantRoot и неизвестные callback wire semantics требуют version-specific proof, не предположения. Correlation подтверждает delivery, не exactly-once server execution. Local lock не исключает native concurrency; same-thread steering принято как допустимое поведение. Административный install/public readiness и реальные phone acceptance не объявляются выполненными этой спецификацией.

## Уточнения границ перед blind RED (05.10)

Cursor: null либо непустая string до4096 chars; upstream nextCursor тот же тип/limit, повтор текущего cursor недопустим. Turn/item IDs: nonempty string до500 chars; Turn.status только completed/interrupted/failed/inProgress. Ownership metadata proof требует object thread с canonical lowercase UUID id и absolute cwd; наличие title/status/settings в metadata-only proof не требуется. Thread listing сохраняет existing public CodexSessions thread/list shape: {data:[thread],nextCursor:string|null}; thread metadata listing содержит id,cwd,status:{type:string}, name/preview optional, updatedAt optional. Существующий нормализатор не заменяет проверки canonical raw UUID.

Private recent lookup не обязан иметь отдельный index. Допускается sealed per-project/thread namespace с bounded enumeration до10000 metadata files, выбором8 latest receipts и проверкой каждого экспортируемого receipt. Отсутствующий ещё не созданный namespace даёт recent_sends:[]; небезопасный namespace, повреждённый/небезопасный прочитанный receipt дают unavailable. Лимит storage исчерпан — unavailable до нового turn/start; существующие записи сохраняются и остаются доступны для dedup. Если используется index, crash/missing/corrupt index не может сделать reserve невидимым и разрешить duplicate send; никакое восстановление index не повторяет turn/start.

RPCRejected возникает только из matching same-generation response с exact typed ID и JSON-RPC error object {code:plain-int,message:string, optional data:any}; message/data не экспортируются. Invalid envelope или matching malformed response — transport/invalid-response failure, после turn/start delivery_unknown. Fake injected RPC может поднять RPCRejected('safe synthetic marker'); и такой error после возможной отправки остаётся delivery_unknown. В этом срезе нет runtime wire кода, доказывающего nondelivery.

## Уточнения по независимому domain adversarial (05.10)

Дедупликация по canonical root/thread/message UUID, а не alias, предотвращает повтор через aliases одного корня; receipt lookup recent_sends использует тот же rootnamespace. Client alias всё равно свежо проверяется до чтения/отправки; по другому root receipt не доступен. RPC error любого кода после turn/start остаётся delivery_unknown: подтверждённый rejected возможен только до возможной отправки при доказанном отказе, этот срез не вводит documented post-send no-accept errors.

Все session операции имеют общий monotonic deadline ≤55s, каждый real RPC ограничен оставшимся временем; existing socket client timeout65s сохраняется. History reconciliation не обязана проходить8pages, если бюджет исчерпан; unknown остаётся unknown. Broker допускает максимум4 одновременно исполняемых запросов с bounded admission; превышение safely unavailable, без вызова backend. Trusted task writers сохраняют native locking и существующие60s deadlines. Этот предел не является автоматическим retry/queue для send.

Запрет paths касается raw структурированных metadata cwd/attachment URL/image/file paths и tool data. Пути внутри allowlisted пользовательского/assistant текста сохраняются как часть авторизованной переписки; этот текст проходит credential redaction, не произвольную замену любых filesystem paths. Не обещать выявление всех secrets/free text.

Native callback delivery между shared clients статической схемой не доказана. Неответ на callback со стороны web доказывается fake wire tests; доступность ответа из native client — отдельный version-specific installed gate до заявления полной интерактивной готовности. UI говорит «Нужно действие в клиенте Codex; ответы из панели пока недоступны», без гарантии, что другой client уже получил callback. При невозможности controlled synthetic shared-client proof chat rollout сохраняется незавершённым; не запускать чужие задания ради проверки и не добавлять auto-response. Это не блокирует подготовку реализации/PR, но блокирует утверждение завершённой production acceptance.

## Уточнения по code compliance (05.10)

Receipt root исключает любой Git ancestor, включая .git directory/worktree markerfile и bare HEAD+objects+refs, только metadata без чтения содержимого. Namespace enumeration считает ВСЕ записи (включая .tmp/junk/lock), предел10002; превышение unavailable до новой отправки, защитные receipts не удаляются. Scandir/open/stat/read loops проверяют monotonic budget до/после операций; deadline55s не обещает прервать зависший kernel filesystem syscall. Existing known receipt остаётся защитой от повторной отправки даже при storage exhaustion.

GET send-status — observational receipt reconciliation: может durable повысить только собственный receipt unknown→accepted по authoritative persisted UserMessage.clientId. GET никогда не вызывает turn/start/resume/ответ native/смену policy; auth/Origin boundary сохраняется. Это явно разрешённое уточнение read status, не новая instruction mutation.

UI older-page cursor живёт отдельно от latest polling: fresh latest response не отматывает уже пройденную older chain; смена thread создаёт/выбирает его собственный bounded history state. Управление кнопками выводится из текущей selected project/thread state, поздний ACK не оставляет другой thread заблокированным и не подменяет его draft/history.
