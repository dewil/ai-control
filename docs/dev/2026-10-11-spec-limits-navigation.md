# Группы лимитов и навигация

Сейчас источники лимитов образуют единый список. Ручное раскрытие проектов после выбора сессии может быть отменено поздним завершением загрузки. Исторический сценарий задержки обработки End требует повторной проверки на текущем r18.

## INV-WLIM26 — группы лимитов

Экран делит существующие карточки на секции в порядке:

- «Локальные»: node=llm, Codex, Claude, Kimi.
- «Облачные»: node=llm, OpenRouter, YandexGPT.
- «ALP»: node=alp, Codex, Claude.

Порядок провайдеров фиксирован. Несколько аккаунтов одного провайдера сохраняют исходный порядок; карточки не дублируются и не теряются. «Локальные» обозначает установленный на LLM runtime, а не исполнение модели на CPU.

Для schema1 отображаются только непустые группы. Schema2 сохраняет существующие карточки ALP с неизвестными данными. Пустые секции скрыты. Закрытый валидатор schema1/2 допускает только перечисленные сочетания node/provider; новые провайдеры и узлы требуют отдельного изменения контракта. Неизвестные сочетания отклоняются до отрисовки; группа fallback не вводится.

Секции имеют семантические h2, карточки — h3. При ширине320/390/1280 нет горизонтального переполнения. Метрики, свежесть, ошибки, weekly×1/×2, API и lifecycle не меняются.

## INV-WSESS47 — ручное раскрытие проектов

Первый успешный ответ истории автоматически сворачивает проекты, если после выбора пользователь не переключал раскрытие вручную. Любой ручной toggle после выбора, до или после первого успеха, делает последнее явное состояние приоритетным до нового выбора/reset. Подтверждение успешного выбора сохраняется даже при отмене автоматического сворачивания.

Новая сессия начинает новый scope намерения. Logout, потеря проекта и начальный экран раскрывают chooser по существующим правилам. Ошибка истории не считается успехом. Новых RPC нет. Reset означает недействительность предыдущего scope; допустима существующая изоляция через монотонный selectionGeneration.

## INV-WSESS48 — возврат к последним сообщениям

Trusted End вне input/textarea/select/contenteditable/dialog, достигший низа документа, возобновляет следование последним сообщениям, включая задержку main thread на1200мс. Принятые realtime-сообщения появляются без ручного клика. Не увеличивать таймауты и не добавлять fetch. Чтение старой истории без End и End в редакторе не переносят к последним; явная навигация вверх отменяет намерение. Изоляция selection/auth/lifecycle сохраняется.

End в editable/dialog не изменяет follow или черновик и не перенаправляет штатную прокрутку на фон. При последующем realtime обновлении оценивается сохранение видимого якоря, а не абсолютного scrollY: изменение высоты страницы может требовать компенсирующей прокрутки.

Если сценарий на r18 уже GREEN, сохранить регрессию без ненужной runtime-правки. Проверено: delayed End и отрицательные сценарии уже GREEN. Первоначальная dialog fixture нарушала CSP; независимый автор исправил её и отозвал ложный RED. Изменений продукта для End нет.

## Проверки и границы

Независимые группы:8 тестов; независимая навигация:10. На baseline группировка RED и ручное раскрытие RED; остальные навигационные сценарии GREEN. Один UI-писатель, независимое ревью Haiku, полный CI точного SHA, подписанный выпуск22files.

Не входит: публикация ALP-экспорта, NATS-управление, approvals, мультиавторизация, новый APK. Авторизация, native runtime и APK сохраняются.
