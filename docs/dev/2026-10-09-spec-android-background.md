# CONTROL-ANDROID-BATTERY — явный lifecycle MainActivity/WebView

Дата: 09.10.2026. Этап: DESIGN, до независимого DESIGN и blind RED. Владелец: `docs/backlog/CONTROL-ANDROID-BATTERY.md`; координация: `CONTROL-SDD-ENERGY-BUS-ROUTING`. Код и production этим документом не изменяются. Usage автора: tokens/money unknown, coverage partial; ledger ведёт root.

## Основание и границы

Повторная широкая диагностика не нужна: исходный отчёт — `docs/research/2026-10-09-android-battery-diagnosis.md` зонтика `/data/sync/obs/dewil/Work/claude-control`. Проверенные исходники: web `/data/git/ai-control-live-observability`, d4d707b62d62b5758de8c65f9b5c7cfd49c77e85; Android `/data/git/ai-control-android-startup-015`, 22f5a71777ac68999851182da576cba4aa404135, APK 0.1.6/code7. Переданное имя Android-папки с суффиксом `22f5a71` отсутствует; использована существующая папка с подтверждённым HEAD.

Web уже прекращает LIVE/BUS при полученном hidden/pagehide. Native блокирует новые WebView loads и вызывает onPause на onStop, но не посылает явный suspend и не останавливает JS timers. Возврат native сейчас может возобновить страницу раньше admission/cookie synchronization. Это установленный разрыв lifecycle, а не доказательство бесконечного фонового polling или измеренного расхода батареи.

Изменение добавляет согласованный native/page lifecycle, удерживает живую WebView, RAM drafts, выбранную сессию/модель и вход. Не меняет `/api/app/*`, bearer/cookie/TTL/TOTP/revoke semantics, providers, model authority, обновлятор/installer и разрешения Android. Не вводит foreground service, wakelock, alarm, WorkManager или просьбу отключить battery optimization. Обычный rotation остаётся под существующим configChanges. Process death/renderer death не обещают восстановления RAM draft; сохранённый device credential восстанавливается по действующему протоколу.

Доменная связь: действующие INV-WSESS-51..53 и LIVEv3 сохраняются. Новые feature-local ID — INV-BATT-01..10; при интеграции добавить их отдельным lifecycle разделом доменной спеки, не переименовывая существующие инварианты.

## Наблюдаемое поведение

Уход MainActivity из interactive состояния (`onPause`, также идемпотентный `onStop`) немедленно закрывает native admission, запрещает новые loads и инициирует suspend страницы. Ожидание acknowledgement асинхронно, главный поток и Activity callback не блокируются. Страница закрывает свой EventSource, abort-ит наблюдательные GET, отменяет LIVE/BUS/retry/renewal/presentation timers и запрещает новые наблюдения. Переход visible сам по себе Android gate не открывает.

Возврат (`onResume`) начинает новую native admission generation. Только после успешного существующего native admission, accepted CookieManager callback и подтверждённого page preflight разрешается page `/api/session`. Его успешный результат подтверждает только готовность page admission. Затем native открывает свой dispatch gate и посылает отдельную activate-фазу того же Resume entry; страница атомарно открывает свой dispatch gate и запускает ровно один транспорт выбранной вкладки. Initial history/refresh не задерживает admission ACK. В sessions SSE по-прежнему имеет HTTP renewal каждые 5000 ms, HTTP lease 15000 ms; fallback/backoff/60 s SSE retry и терминальные 401/403 сохраняются. BUS не монтируется одновременно с sessions LIVE.

Login без отправки сохраняет те же EditText, текст, selection и focus при уходе/возврате. Успешный вход, явный logout, подтверждённый terminal revoke и renderer death сохраняют свои существующие последствия; это отдельные причины очистки, не последствия background.

## Публичный контракт v2 и совместимость

Новый APK добавляет к текущему WebView User-Agent фиксированный маркер `AiControlLifecycle/2`, сохраняя остальной UA. Это только согласование версии, не доверенная auth capability. Новых JavascriptInterface методов/полномочий нет. Существующий bridge остаётся fixed-origin. Новый web при наличии AndroidAuth и этого маркера стартует в состоянии `suspended`; desktop и старый APK используют совместимый legacy путь.

Новый web экспортирует:

- `window.aiControlAndroidLifecycleProtocol()` → число `2`.
- `window.aiControlAndroidSuspend({protocol:2, serial:N})` → объект `{protocol:2, action:'suspend', serial:N, ok:true}` после синхронных close/abort/cancel/invalidation. Вызов через evaluateJavascript асинхронен для native; возврат функции не является доказательством физического TCP disconnect.
- `window.aiControlAndroidResume({protocol:2, serial:N, phase:'admit'})` → Promise<boolean>. Больший serial переводит page gate в `admitting`, допускает единственный credentialed GET `/api/session`. Успех при сохранённом serial/видимости записывает csrf/готовность в RAM, переводит gate в `ready` и возвращает true. `ready` не разрешает ни observation dispatch, ни mutations и не запускает initial history. Ошибка/утрата актуальности возвращает false с закрытым gate.
- `window.aiControlAndroidResume({protocol:2, serial:M, phase:'activate', admissionSerial:N})` → Promise<boolean>, где M>N. Только текущая ready generation с admissionSerial N может синхронно принять M и атомарно перевести page gate в `active`; после этого она запускает initial reads/selected transport без await и возвращает resolved true. У activation нет server IO. Ошибки initial reads обрабатывает существующий visible transport/UI контракт, а не admission retry. Неверный/stale admissionSerial возвращает false, не открывая gate. Это две фазы одного существующего entry, без нового bridge/endpoint.
- `window.aiControlAndroidResume()` без аргумента сохраняет старый контракт **только для Android без v2 UA marker**. Для v2 marker такой вызов возвращает false. Старый APK не получает несовместимой обязательной native capability.

Serial — положительное JS-safe integer, строго возрастающее для каждого native lifecycle command в пределах живой Activity/WebView. Нельзя брать существующий auth epoch за serial: auth epoch меняется и по другим причинам. Новый экземпляр страницы имеет свою identity в native; callback всегда связывается с конкретной WebView identity, navigation generation, lifecycle generation, auth generation и command serial. Navigation generation увеличивается на main-frame onPageStarted, немедленно закрывая native gate и инвалидируя старые callbacks. Проверка protocol и вызов соответствующего entry выполняются в одном evaluateJavascript wrapper текущей navigation generation, без отдельного check-then-call окна; callback другой navigation generation отвергается. При исчерпании диапазона serial не оборачивается; удерживается gate с явной ошибкой (практически недостижимо). На странице команда с serial меньше принятого игнорируется; одинаковый suspend идемпотентен и возвращает тот же ACK, одинаковый resume serial/phase coalesce-ится в тот же Promise/результат; смена phase с тем же serial отвергается. Native использует новый serial для preflight suspend и ещё больший для resume: поздний старый suspend не закроет уже принятую новую generation.

ACK возвращается фиксированным evaluateJavascript wrapper через JSON.stringify. Native валидирует callback как JSON-encoded string, затем объект, exact protocol/action/serial/ok. `null`, missing, exception, malformed, чужая identity/generation и поздний результат не равны ACK. Никаких bearer/cookie/CSRF в JS командах, ACK, UA или логах.

Resume сохраняет result slot + bounded native polling: slot содержит serial, phase и ok; Promise completion пишет только при актуальных serial/phase. Native опрашивает не чаще 100 ms, без overlap evaluate. Для admit независимый Handler deadline **10 s** включает только GET `/api/session` и его CSRF validation; initial history/refresh/SSE сюда не входит. Для activate отдельный deadline **500 ms**: это локальная JS операция без сети. Deadline действует и если evaluate callback не пришёл. Вновь начатая generation отменяет старые deadlines/polls.

Любой failed/missing/malformed/timeout результат admit/activate сначала закрывает native dispatch/network gate и отменяет polling, затем выполняет **один** fenced best-effort v2 suspend с большим serial и 500 ms ACK deadline: вызывает только function `aiControlAndroidSuspend` с `{protocol:2,serial}`, если она существует; иначе не вызывает ничего и ждёт тот же bounded deadline. Legacy/no-arg entries не вызываются. Только ACK либо этот deadline разрешает WebView.onPause/pauseTimers. При responsive renderer это отменяет admitting/ready/active до заморозки; поздние Promise completions fenced новым serial. При unresponsive renderer результат честно unconfirmed. После этого нет автоматического reload/admission/retry loop; обычный transport failure предлагает explicit retry, BLOCKED_UNCONFIRMED только explicit reprobe, UNSUPPORTED_WEB только manual restart по compatibility контракту. Таким образом завершение отменённого admit не активирует страницу: admit никогда сам не открывает dispatch gate, а activate требует retained current ready proof.

## Native переходы и конечный fallback

1. `onPause`: синхронно interactive=false; invalidate lifecycle/admission callbacks и gate; убрать native periodic callbacks; setBlockNetworkLoads(true). Для живой страницы в одном fixed evaluate текущей navigation generation проверить protocol/entry и вызвать существующий v2 Suspend с новым serial; если entry отсутствует, ничего не вызывать. Завести один deadline **500 ms**, после которого native pause выполняется даже без entry/ACK. `super.onPause()` не ждёт ACK. `onStop` повторно закрывает native gate, но не создаёт вторую операцию suspend, если она уже активна/завершена. Updater foreground bookkeeping сохраняется на onStart/onStop; panel admission переносится на onResume.
2. ACK текущей операции: один раз вызвать WebView.onPause() и pauseTimers(), записать `suspend_confirmed`. Deadline удалить. Если ACK не получен к deadline: те же onPause/pauseTimers, состояние `suspend_unconfirmed`. Дополнительных JS попыток в фоне нет. Для незагруженной страницы stopLoading допустим как остановка незавершённой загрузки, но не считается доказательством закрытия EventSource.
3. После fallback не уничтожать/перегружать WebView, не выполнять about:blank, clearCache, deleteAllData, clearHistory или credential clear. Не менять pageLoaded на false лишь из-за отсутствующего suspend/resume ACK: существующий installCookie destroy branch иначе уничтожит RAM на повторе.
4. Deadline ограничивает **ожидание** ACK, когда главный поток обслуживается. Он не обещает выполнение native кода во время заморозки/убийства процесса ОС. Запрет новых native loads выставлен до ожидания. ACK подтверждает выполненные page операции close/abort/cancel, не уничтожение уже принятой серверной работы.
5. Возврат до ACK/deadline отменяет его право замораживать новую foreground generation. Сначала существующий native POST admission и CookieManager acceptance с новым lifecycle fence. Пока они не завершены, network block и timer pause сохраняются. При успехе resumeTimers()/WebView.onResume() при **ещё закрытом network block**, затем page preflight suspend с новым serial и 500 ms ACK deadline. Он требуется после confirmed и unconfirmed stop. После ACK снять network block в режиме native `ADMITTING`, допускающем только GET `/api/session` среди API; вызвать Resume phase=admit с большим serial. Page тоже разрешает только этот GET. Получив текущий admission true, native **сначала** переводит свой dispatch state в `ACTIVE`, затем вызывает Resume phase=activate с ещё большим serial и admissionSerial предыдущего admit. До этого page `ready` запрещает все observations/mutations. Activate атомарно открывает page dispatch gate и запускает initial reads без await. Native overlay остаётся поверх страницы до текущего activate true; после него скрывается. Ни на одном штатном activation шаге page не разрешает mutation при native ADMITTING.

Первая загрузка использует отдельный `BOOTSTRAP` после успешных native admission/cookie. Network block снимается только для shell assets; native interceptor разрешает **ровно** GET paths `/`, `/web.js`, `/web.css`, `/devbus.js`, `/devbus.css`, `/favicon.svg`, `/favicon.ico`. Query разрешён только у `/` для существующих deep links; остальные перечисленные paths требуют пустой query. Все другие методы/paths и все `/api/*` в BOOTSTRAP отклоняются. `/favicon.ico` — существующий redirect на разрешённый `/favicon.svg`; это не wildcard. Existing origin/method/navigation policy применяется дополнительно, не заменяется этим списком. Набор exact и не расширяется автоматически по содержимому shell.

Новый web с UA marker стартует suspended и не делает API до v2 admit. По onPageFinished текущей WebView/navigation/lifecycle native выполняет проверку реального protocol function→JSON number2 **и вызов preflight entry в одном evaluateJavascript wrapper**. Аналогично admit/activate проверяют protocol и вызывают нужный entry одним evaluate текущей navigation generation; отсутствие/смена generation закрывает gate. UA marker определяет только APK, не версию web.

Missing/malformed/throw protocol или required entry первоначально/позже → UNSUPPORTED_WEB: native network/dispatch block; один fenced best-effort v2 Suspend с большим serial **только если именованный Suspend entry является function**, всегда со structured `{protocol:2,serial}`. Если его нет, никаких entry calls; native ждёт bounded500ms и делает onPause/pauseTimers. При ACK pause раньше; null/missing не ACK. Legacy/no-arg Resume никогда не вызывается. WebView/RAM/device credential сохраняются. Overlay требует обновить веб и предупреждает о единственном manual exit: «Обновите веб-панель на сервере, затем вручную перезапустите приложение. Несохранённый черновик будет потерян; сохранённый вход останется». Агент/приложение не инициирует restart/reload/destroy/clear и не добавляет новую UI reload/restart кнопку. Exit — только пользовательский перезапуск после обновления web; новый процесс получает fresh page и восстанавливает credential обычным admission. До restart RAM удерживается.

Unresponsive protocol/entry eval → BLOCKED_UNCONFIRMED, network/dispatch остаются закрыты, page paused после bounded500ms; нет unsupported-version утверждения и нет automatic admission/retry даже при следующем onResume. Overlay сообщает отсутствие ответа и предлагает только явную повторную проверку. Эта проверка временно размораживает timers при закрытой сети и одним wrapper проверяет protocol+preflight; только подтверждённый protocol2 позволяет явное продолжение обычного admit/activate. Повторно unresponsive остаётся blocked. Manual restart допустим с тем же предупреждением о RAM, device credential не удаляется.

BOOTSTRAP имеет независимый load deadline 10 s. Timeout закрывает network, выполняет один conditional v2 best-effort fenced suspend по указанному правилу exists/500ms и замораживает, сохраняя страницу. Поздний onPageFinished может отметить готовность retained shell, но не открывает dispatch. Явный retry повторяет probe/resume на retained finished странице; если начальная загрузка фактически не завершилась, retry может повторить **только первоначальную незавершённую shell load**, у которой ещё нет authenticated рабочей страницы/черновика. Готовую RAM-страницу не reload/destroy. Повторять load автоматически запрещено.

6. Failed preflight/admit/activate: немедленно native network/dispatch block, затем больший-serial conditional v2 best-effort suspend только при существующем named entry, иначе bounded500ms без entry call; onPause/pauseTimers **после** его ACK/500 ms deadline, не до JS cancellation. Если protocol/entry eval unresponsive, состояние BLOCKED_UNCONFIRMED остаётся network/dispatch-blocked без автоматического admission; допустим только explicit reprobe. Если уже выполнялся failed preflight suspend, его завершённый 500 ms deadline достаточен: второго бесконечного ожидания/повтора нет. Retain WebView и foreground error overlay; explicit retry относится к transport failure/reprobe unconfirmed, а UNSUPPORTED_WEB имеет только manual-restart exit по compatibility контракту. Offline/503 не очищает credential; documented terminal outcome сохраняет действующий terminal path. Late ACK/HTTP/Cookie callbacks не открывают gate/не скрывают overlay/не ставят renewal. При failure пользовательский ввод overlay блокирует; на странице каждый mutation handler и общий mutation dispatch повторно проверяют page active/visible до создания UUID/receipt/unknown/inFlight/busy и fetch. Refused predispatch action показывает «Панель восстанавливается», сохраняет draft, не создаёт delivery_unknown. Нет очереди мутаций для automatic dispatch после activate. Уже начатые до suspend mutations имеют отдельный existing reconciliation контракт.
7. `pauseTimers` глобален для WebView процесса. В текущем APK WebView принадлежит MainActivity; явный ownership флаг управляет одной парой pause/resume. Duplicate stop ничего не добавляет. При окончательном onDestroy порядок строго такой: немедленно network block и invalidate callbacks; если ownership pause установлен, создать локальную пустую detached WebView только как timer-cleanup receiver (без JS, bridge, URL/load и состояния приложения); удалить page WebView из root и bridge; вызвать **page WebView.destroy()**; обнулить native web; только **после page destroy** вызвать `resumeTimers()` у пустого receiver, очистить ownership и destroy receiver. Вызывать методы на уже destroyed page WebView нельзя. Receiver не является второй активной страницей и ничего не загружает; если паузы нет, он не создаётся. Живая background страница не возобновляется между pause и destroy. Recording host проверяет destroy-before-global-resume; device smoke подтверждает cleanup receiver/global API call и работоспособность нового экземпляра. Нет вызова onResume/evaluate/loadUrl на destroyed странице. Future второй активный WebView требует отдельного ownership решения.

**Граница fallback:** WebView API не даёт подтверждённого недеструктивного способа принудительно закрыть уже открытый SSE у неотвечающего renderer. Поэтому `suspend_unconfirmed` гарантирует запрещение новых native loads и выполненный native timer pause, но **не** утверждает закрытие ранее открытого соединения. Это явный degraded результат, не PASS «ноль фоновой сети». При foreground повторе живой renderer сначала подтверждает preflight и закрывает старые transports; при реально умершем renderer действует существующий onRenderProcessGone. Если в здоровой device matrix ниже есть хотя бы 1 suspend_unconfirmed из 20 циклов либо хотя бы 1 новый panel request после ACK, релиз по battery приёмке не проходит; нельзя замаскировать это blanket destroy или обещанием TCP cancellation. Принятый размен — сохранность RAM и bounded ожидание вместо ложной гарантии для неотвечающего renderer.

## Ограниченный объём реализации

Основные поверхности: MainActivity.java (lifecycle, timer ownership, fenced eval/deadline, UA version), _control_web.js (gate, entrypoints, registry наблюдательных AbortController и cleanup), BUS mount boundary для shared gate. Затронуть только необходимые host stubs/fixtures/spec/tests. Общая API функция должна проверять captured lifecycle **до** auth side effects и до возвращения success; caller completion guards нужны там, где есть дополнительный await. BUS собственный fetch wrapper принимает тот же lifecycle fence. ControlDevbus transport semantics не переписываются.

Мутации остаются отдельным классом: suspend не отменяет POST, не повторяет его и не вызывает signedOut от stale background response. Нельзя просто оборвать все fetch одинаково и забыть sendsInFlight/unknown receipt. На resume текущие unresolved попытки получают существующее честное состояние/ручную проверку; automatic delivery check/replay не добавляется. Presentational timers clear-ятся без стирания данных; lease при suspend становится невалидной и после resume заново подтверждается HTTP.

UA обозначает только APK. Protocol check и соответствующий preflight/admit/activate entry call выполняются **одним evaluateJavascript** той же WebView/navigation generation; stale callback отвергается. Отдельный probe не разрешает поздний call.

Missing/malformed/throw protocol/required entry первоначально или позже немедленно блокирует native network/dispatch. Выполняется один больший-serial Suspend **только если v2 named entry существует как function**, исключительно с `{protocol:2,serial}`; иначе нет entry calls. ACK либо deadline500ms приводит к onPause/pauseTimers. Legacy/no-arg calls запрещены. Retained WebView/RAM/credential не очищаются.

Unresponsive eval остаётся BLOCKED_UNCONFIRMED с закрытыми network/dispatch и bounded pause, без ложного unsupported-version вывода. Automatic admission/retry, включая onResume, запрещён. Только explicit reprobe: timers временно размораживаются при закрытой сети; единый protocol+preflight wrapper при успехе допускает явное продолжение admission, иначе остаётся blocked.

UNSUPPORTED_WEB overlay: «Обновите веб-панель на сервере, затем вручную перезапустите приложение. Несохранённый черновик будет потерян; сохранённый вход останется». Единственный exit — **ручной app restart** после обновления web. До него RAM сохраняется; restart теряет RAM, но не очищает stored credential, который восстанавливается штатно. Нет нового UI reload/restart flow, автоматического restart/reload/destroy/cache или credential clear. Manual restart при unresponsive также требует предупреждения о RAM.

R9 проверяет реальные runtime entries с одинаковым newAPK UA, initial/later malformed, отсутствие legacy calls, conditional Suspend/500ms, navigation race, blocked-unconfirmed/noautoadmission и RAM/credential retention до manual restart.

## Device gate (пока NOTRUN)

На том же S23 Ultra / Android15 записать Android/WebView версии, APK version/code/hash и web asset revision, сеть, charging state, brightness, длительность/температуру/start SOC. До code7 и после candidate — сопоставимые окна без force-stop как замены background. Package/его WebView renderer CPU, request/path counters и агрегаты UID bytes собираются без payload/token/cookie/chat contents; отсутствие доступного oracle отмечается NOTRUN, не PASS. Нет reset batterystats и полного приватного logcat.

Release behaviour gate имеет фиксированную матрицу **20 здоровых циклов**: sessions Home 5, sessions screen lock 5, BUS Home 5, BUS screen lock 5; каждый цикл background >=65 s, затем возврат. Сеть исправна, native/page admission заранее успешен; pending renewal/retry активируется контролируемо как минимум в одном цикле каждой группы. Требования: **20/20** suspend ACK <=500 ms (0 suspend_unconfirmed), **20/20** activate ACK <=500 ms после admission, один fresh selected transport на возврате, 0 случаев утраты RAM draft/receipt/selection/login fields. Admission `/api/session` должен дать ACK <=10 s, initial history может завершиться позже без admission timeout. Неисправный renderer/missing entry/offline — отдельная fault matrix: bounded unconfirmed/blocked outcome ожидаем и не включаем его в здоровые 20/20; для него требуется честная диагностика и сохранность RAM, не full quiescence claim.

В каждом healthy background окне счётчик **новых** panel requests после suspend ACK и до начала возврата равен **0** (учитываются LIVE/lease/BUS/tasks/projects/history/model/session GET; уже начатый до ACK ответ не новый request). Новых EventSource/retry/timer chains — 0. На foreground возврате max одновременно активных выбранных transports=1. Page close/abort подтверждается local instrumentation; для server stream после **наблюдаемого disconnect/write failure** освобождение <=25 s по существующему LIVE контракту. Для proxy-accepting blackhole абсолютного 25 s нет: не считать задержанный server slot доказательством page polling, результат отдельно unknown до detectable failure; не вводить forced stream lifetime.

Отдельные idle окна baseline/candidate: sessions и BUS, для каждого foreground 5 min → Home 15 min, затем fresh run foreground 5 min → screen lock **30 min**. Во время окон нет updater/auth/download/install operation после начального settle 30 s; если они начались, окно недействительно и повторяется после их existing bounded завершения. Wi-Fi/мобильный тип и состояние сигнала одинаковы, brightness неизменна, нет зарядки; старт SOC в пределах 5 процентных пунктов, старт battery temperature в пределах 2°C. Native activity startup/return исключаются из idle CPU interval.

CPU oracle в candidate: aggregate CPU time package + принадлежащего ему WebView renderer после settle увеличивается **не более 1.0 s на каждое неперекрывающееся 5 min idle окно** и **не более 250 ms в любом 60 s sample**; app-owned periodic wake/timer chains=0. Это выбранные acceptance ceilings для supported device, не обещание Android scheduler. Любое превышение — FAIL с конкретным интервалом; нельзя усреднить его между долгими quiet окнами. New panel requests в этих idle окнах также 0. UID bytes фиксируются, но не требуют буквально zero: TLS teardown/OS accounting/ранее начатые bounded операции отличаются от повторных panel requests. При недоступности attributed renderer CPU gate остаётся NOTRUN.

Destroy-before-global-resume и новый экземпляр WebView проверяются на устройстве один раз, recording host — на каждом соответствующем тесте. Native diagnostics содержат только protocol/state/serial/outcome/elapsed, не секреты.

Измеренный **power improvement** — отдельное утверждение: нужны минимум **3 paired baseline/candidate idle окна одинаковой длительности** для sessions Home и screen lock с указанными условиями. Отчёт содержит все charge-counter deltas/rates и разрешение измерителя, медианы, CPU/network evidence. «Снижение» можно утверждать лишь если candidate median discharge rate как минимум на **10% ниже baseline**, абсолютная разница превышает разрешение измерения, и candidate не хуже baseline в каждом из трёх paired окон. Иначе результат power **inconclusive/no confirmed improvement**, даже если lifecycle/network/CPU release gate PASS; battery% короткого окна этого не заменяет. Ни один synthetic/host тест не считается измерением энергии.
