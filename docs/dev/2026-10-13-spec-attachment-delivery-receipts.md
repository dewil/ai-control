# Attachment delivery receipts after native image transformation

Proposal, incident r30, 13.10.2026; parent CONTROL-WEB-ATTACHMENTS. Native Codex can resize/reencode a local image. Delivery must not become permanently unknown merely because its image bytes differ. `accepted`/`queued` attest delivery, never pixel equivalence or consumption.

INV-WATT-DELIVERY-01: retain exact `normalized_input` and original manifest/inode/SHA/size checks for pinned source integrity. Add a separate delivery matcher after trusted native ACK, or a unique exact clientId history item in the same verified SID/context. User text, canonical generic-file instruction, part order/type/count remain exact. localImage paths must equal the pinned path. Inline PNG/JPEG requires canonical base64, <=2MiB decoded bytes and existing structural/resource image checks; transformed inline bytes may differ from the original. Unknown part fields, unsupported image detail, malformed media, wrong text/order/type/count/path fail closed. This is a versioned delivery projection; do not report transformed hashes as original hashes.

INV-WATT-DELIVERY-02: history reconciliation counts every same-MID native user item. Exactly one candidate with a valid delivery projection may resolve accepted. Duplicate same-MID candidates, even identical, and any conflicting candidate remain unknown. A text-only match cannot acknowledge an attachment. No reconciliation issues native mutations, retries a send/enqueue, releases pins or weakens current owner/root/SID/context/grant fences.

INV-WATT-DELIVERY-03: common GET session-send-status and dedicated attachment receipt use the same attachment reconciler selected by the durable per-MID receipt kind. This supports manual checks and fresh browser reload without relying on latestAttempts. Owner-authorized historical read scope remains server-derived; no browser auth/scope bypass. Reuse a helper and avoid nested namespace locks. Recovery updates the protected receipt and shared receipt consistently; repeated status reads are idempotent and retain original pins.

Tests use synthetic valid1x1PNG images with different pixels, ordinary generic bytes and isolated ASGI/native fixtures. No private image or paid inference. Diagnostic author inspected prior implementation to locate the incident; these are independent contract regressions, not a clean-context blindness claim. Usage unknown; parent owns ledger. Existing transport/auth boundaries and direct-send semantics remain.

Clarification: image detail is only absent/None/auto, as in the original contract. Inline image correspondence uses ordered position and trusted native UUID attribution; this does not establish pixel equivalence. Corrupt shared receipts or mismatched shared/spool commitment digests must refuse reconciliation before any accepted result.
