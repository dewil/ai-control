## Generator interface and provenance

Planned `scripts/build_node_transport.py` exports `generate(source: pathlib.Path, output: pathlib.Path) -> dict` and CLI `--source PATH --output PATH`. Both paths are explicit; no config/env/credential search, network, import/execution of source, systemctl, SSH, apply or default destination. Source bytes must match SHA256 `bb871ccb80d7fbf6b620ba40d2521ed65dc8ac6eca8a469606b59f8b9b2bb70e` before transformation. Different bytes, missing source, symlink input/output, existing output, same source/output, or output within `/data/git/agent-bus` or installed/ALP destinations fail without changing anything. Candidate is a local review artifact only. Public success metadata contains only upstream SHA, candidate SHA and artifact schema; no arbitrary source bodies or exception strings.

Unchanged fixture `tests/fixtures/node-transport/upstream_transport.py` is external reference data. Its SHA/provenance is pinned in sibling `provenance.json`; it contains no credential values. Tests never import actual nats or access actual source/config/runtime. Generator must also accept this exact fixture, so tests require no live upstream filesystem. Candidate stays importable as the existing devbus transport module; no new dependency or framework.

Candidate output creation MUST use atomic create-only `O_CREAT|O_EXCL`, never truncating/opening an existing destination for writing. Validate allowed roots and path ancestry using directory descriptors and `O_NOFOLLOW`: reject symlink ancestors before applying the output allowlist, and open the final output relative to the validated parent dirfd. Do not resolve a symlink to an allowed target and then accept it. Reject any symlink source ancestor or final component too; preserve source and existing output bytes on every rejected operation. The output is one local artifact, not a deployment transaction.

## Candidate behavior

`Broker.connect` validates `DEVBUS_NATS_URL` and credential mode before `nats.connect`. URL must have no username/password; absent URL fails. No auth values enter URL, command arguments, prints, exception text or metadata. Supported `DEVBUS_NATS_AUTH_MODE` values are exactly token, creds, user_password. Explicit token/creds mode requires its matching nonempty TOKEN/CREDS value and forbids any other auth values. user_password requires nonempty USER+PASSWORD and forbids TOKEN/CREDS. Unknown/empty explicit mode, mixed values and incomplete pair fail before I/O. Absent MODE preserves unambiguous existing token or creds configurations, and rejects USER/PASSWORD or missing credentials. Empty unused auth variables are treated as absent; empty selected values are invalid.

Pass token/user_credentials/user+password to nats-py through the matching kwargs only. In user_password mode set connection `inbox_prefix=b'_INBOX.alp_codex_runner'`. The config remains fixed to this pilot; username is not used to construct a subject. Freeze validated mode in returned `broker.auth_mode`; later environment edits cannot change resource mutation behavior. Constructor remains compatible with existing `Broker(connection, js, config)` callers, with legacy mode as default; `connect` sets the validated mode explicitly.

In user_password mode `ensure_stream` inspects the existing stream and applies existing FILE/limits/TTL/bytes/subject checks; NotFound propagates/generic failure with zero add_stream calls. It never creates/updates/deletes a stream. Legacy token/creds behavior remains as upstream, including existing stream creation semantics.

In user_password mode `commands(agent)` first refuses `agent != config.agent_id`, inspects exact preexisting `dispatcher-<agent>` via `js.consumer_info(config.stream, durable)`, and checks explicit ACK and exact command filter before binding. Missing/mismatched info never creates or binds. Bind only through `js.pull_subscribe_bind(stream=config.stream, consumer=durable, inbox_prefix=b'_INBOX.alp_codex_runner.')`, cache only a successful validated binding, then fetch one with timeout1. No pull_subscribe/add_consumer/create API. Failed validation must not poison cache; a later corrected inspection may bind. No task-controlled inbox. Preserve timeout→empty-list behavior. Legacy token/creds commands behavior remains upstream. Normal runner agent_id is fixed by the approved profile; it is not provided by a web task.

`events()` remains manual owner/admin CLI behavior; the runner never calls it. Runtime runner identity therefore needs no events history CREATE permission. This patch does not add epoch attestation absent from Config; source/stream/consumer epoch deployment checks remain a separate required contract. It does not implement publisher, new protocol fields, cancel/retry, usage, or auth migration.

Additional fail-closed requirements: reject URL userinfo (including empty userinfo), query and fragment in every auth mode. Reject selected credentials consisting only of whitespace, while passing any nonblank credential bytes unchanged, without stripping them. Before strict command binding, consumer INFO must also report `stream_name == config.stream` and `name == durable`; absent or mismatched SDK fields fail before binding. Frozen auth mode governs commands as well as stream handling, even if the process environment changes after connect. Legacy token and creds commands continue to use the existing pull_subscribe path.

## Verification and remaining decisions

Independent RED `tests/test_node_transport_generator_red.py` exercises generated candidate in an entirely fake nats module tree and synthetic config/env. `CONTROL_NODE_TRANSPORT_BASELINE=1` deliberately exercises the pinned original fixture to demonstrate semantic gaps, not readiness. Normal mode requires the planned generator and generated output. Both fixture provenance and generated output are checked locally; no live credential is needed.

Before GREEN, root must review whether the explicit local output allowlist should restrict generation further than the forbidden deployment roots. Proposed generator rejects `/opt`, `/usr`, `/etc`, `/home`, `/root`, `/data/git/agent-bus` destinations and accepts only a new file beneath `/var/tmp` or `/tmp`; it never creates parent directories. This is the required minimum for this implementation. Root may narrow the allowed roots before code. Ensure source and destination resolution/symlink checks cannot route writes through an alias to a forbidden root.

Also confirm the caller is CLI-main (`ensure_stream` then dispatcher run) and passes fixed config.agent_id. nats-py2.9.0 `pull_subscribe_bind` accepts consumer/stream/inbox_prefix and performs no consumer create; this SDK source was inspected locally. Disposable whole-runner ACL/reconnect evidence remains required after implementation, beyond mocks. The strict epoch/binding checks from the auth spec must not be declared implemented by this smaller transport patch.
