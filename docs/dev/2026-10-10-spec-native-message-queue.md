# CONTROL-SESSION-MESSAGE-QUEUE — native queue integration

## Problem and intent
Messages sent while an agent works must appear immediately in chat, wait for the next turn by default, and remain visible after reload/closing the phone. Operator may cancel a queued message or explicitly send it into the active turn. Shared desktop/web sessions must not receive accidental steering from an idle/start race.

## Evidence and chosen architecture
User10.10 chose native queue where exposed via API, otherwise a durable Control queue. Installed Codex0.161 exposes experimental thread/queue/{add,list,update,delete,reorder,start}; read-only queue/list has passed against the actual server. Native queue/start and auto dispatcher call start_turn_if_idle, unlike turn/start. Use native storage/ordering/dispatch as sole pending authority for this adapter; no parallel Control pending queue or completion pump. Other vendors retain existing behavior and explicitly report queue unsupported until separately implemented. Do not falsely call immediate send queued.

This draft supersedes the earlier0.160 finding only for native queue operations proved in0.161. Queue is experimental: capability is method/context-specific, not a blanket trust of a version string. No native auth/config/service restart is part of integration. General read-only capability negotiation stays a linked separate child.

## Invariants
INV-SQUEUE-01: Pending native rows are scoped to canonical project root, exact full thread ID and admitted native transport/context. Frontend never supplies account/socket/path. Existing origin, peer UID, generation, root and CSRF/Origin checks remain. No session/account reassignment.

INV-SQUEUE-02: Enqueue UUID is immutable and durably reserved before native add under the existing per-thread receipt lock. Exact retry does not invoke add again; a different payload under same UUID fails. clientUserMessageId is correlation, not vendor dedup. Failed/lost add ACK stays delivery_unknown and never auto-adds again. Reconciliation may prove queued via native row/clientID or accepted via actual history; absence proves neither loss nor permission to resend.

INV-SQUEUE-03: Native queue is authoritative for order, persistence and automatic advancement. Control must not call turn/start for ordinary queue delivery. Queue add may dispatch immediately if idle, so ACK means native accepted the enqueue request; UI resolves queued versus accepted from queue/history. Native queue/start atomic idle failure never falls back to turn/start/steer. Interrupted native turns may leave queue paused according to vendor behavior; report that honestly.

INV-SQUEUE-04: Queue list is bounded/paginated, validated and generation-fenced; malformed, duplicate IDs/clientIDs, wrong input shape or incomplete pagination do not authorize mutations. Pending native rows from Mac also appear; not only Control recent receipts. queue changed is an invalidation hint, not replay authority. Phone background closes SSE as before; native execution does not depend on observers.

INV-SQUEUE-05: Cancel uses native delete under its native dispatch guard. deleted=true means removed before native start; false means already gone/changed, not cancelled. Lost delete ACK stays unresolved and must not change UI to cancelled without proof. Repeated commands cannot accidentally target a later row under reused ID. Existing Control UUID records remain non-replayable.

INV-SQUEUE-06: Send now targets a captured exact active turn via turn/steer(expectedTurnId). Never use turn/start or successor fallback. Native API has no atomic queue-to-steer move. Before deleting, durably preserve the selected payload plus action UUID/target in owner-private storage using existing filesystem fences. Only a confirmed native delete=true permits one steer attempt; false/error/unknown forbids steer. Reserve that attempt durably before wire. Crash/timeout after possible wire stays delivery_unknown, payload available for diagnosis, no automatic replay or requeue. Target changed rejection retains a recoverable unsent item with explicit status; it must not disappear. Other pending rows retain native order. This transfer is not exactly-once across native crash; no such claim.

INV-SQUEUE-07: Native add/start does not accept model/effort. Queue mode inherits session settings at actual dispatch, labelled clearly. Explicit overrides must not be silently dropped, applied to all queued messages, or simulated via turn/start; reject unsupported queued override before native mutation and preserve draft. Existing immediate explicit-send behavior remains only under an explicitly chosen immediate mode. Send now does not change active turn model/effort.

INV-SQUEUE-08: Bubble appears immediately with sending/enqueueing state, becomes queued only after native enqueue ACK/proof; accepted and delivery_unknown are separate states. Pending bubbles restore from native queue on reload. History clientID reconciliation avoids duplicate queued/history bubbles. Stale async responses cannot regress state or cross session scope. Compact cancel/send-now controls show unsupported/unknown reasons. Draft clears only after durable accepted enqueue, matching existing draft ownership rules; navigation/scroll/mobile/lifecycle behavior preserved.

INV-SQUEUE-09: Bound local recovery payload and remove it after terminal resolution; never expose raw RPC errors or secrets, never write pending text into Git/sync. No new service/queue credential/account binding changes. Native retention/crash semantics are reported separately: source shows persisted SQL rows but start and deletion are not one transaction. Control cannot guarantee absence of a vendor-side replay after native crash.

## Public contract (to freeze after independent design check)
Keep current immediate /api/session-send compatibility. Add POST /api/session-queue with project,sid,message_id,text and optional selection; inherit selection only for supported native queue. GET /api/session-queue?project=&sid= returns validated bounded rows plus capability/reason. POST /api/session-queue-cancel with project,sid,queued_submission_id,action_id; POST /api/session-queue-send-now additionally expected_turn_id. All mutations reuse existing auth/strict Origin/CSRF/DTO/same-UID broker routing. Broker/SessionChat operations mirror endpoints. No private paths/account names in public DTO. Read response must explicitly say partial when bounded pagination cannot finish.

## Acceptance
Independent blind RED precedes implementation. Cover enqueue ACK loss/duplicate UUID, simultaneous clients, native idle race/start-only, queue+history dedup, cancel versus dispatch, delete ACK loss versus steering, crash points before/after transfer reservation and wire, changed target, explicit model refusal, native rows from another client, pagination corruption/context/account change, restart, expired auth, 320/360px geometry and background lifecycle. Native acceptance uses isolated dedicated test thread and bounded messages, never current production work thread. Real desktop interoperability and native restart crash matrix remain separate evidence, not implied by mocks. Full CI and independent SOURCE review on exact integrated SHA before release.

## Frozen core / separate pending transfer decision
Enqueue/list/cancel/UI core is frozen for independent RED. Busy send-now transfer INV-SQUEUE-06 remains DESIGN ONLY, not authorized for implementation until user answers concurrent-edit snapshot question; test unsupported capability now. Neither tests nor implementation may silently call queue/start as busy steering. Native cancel by item ID intentionally cancels the item regardless of edits; this differs from move-to-steer.

## Exact core DTO and seams for independent tests
SessionChat exposes queue(project,sid), enqueue(project,sid,message_id,text,selection=None), cancel_queued(project,sid,queued_submission_id,action_id). Broker backends expose session_queue/session_enqueue/session_queue_cancel. All return JSON-compatible dictionaries. queue result: schema=1, vendor=codex, supported boolean, reason string-or-null, rows list, partial boolean, send_now_supported=false. Each row: queued_submission_id (bounded opaque string), message_id (bounded native clientID, not necessarily UUID for Mac rows), text string, state=queued. Native rows with non-text inputs may be represented as unsupported-input placeholders with cancel disabled, never silently discarded or sent with truncated content. Queue IDs/clientIDs are distinct. Mutations accept UUID Control message_id/action_id and bounded native queued_submission_id. Invalid shape errors use existing SessionError invalid_request/unavailable/stale model; unsupported selection is rejected before add with explicit queue_unsupported_selection code and no draft clearing. Native non-text/overflow/invalid response cannot authorize cancellation.

Enqueue returns status=queued or delivery_unknown, message_id, queued_submission_id string-or-null. Do not claim accepted/completed solely from add; accepted history may already supersede enqueue ACK in UI. Cancel returns status=cancelled only for deleted=true, otherwise status=changed (false) or delivery_unknown (ambiguous), message_id=action_id, queued_submission_id. Repeating an action UUID with same target returns stored result without delete; different target fails invalid_request. All payloads same scope/context/root fencing as send.

Native listing: limit64 per page, max4 pages/256 rows, max16000 chars per rendered text and bounded aggregate text4MiB. nextCursor must be null or bounded nonempty string without cycle. Unfinished budget returns partial=true and cannot prove absence; rows/IDs validated before exposing commands. Capability unavailable is explicit supported=false reason=unsupported_queue, rows=[], partial=false; unrelated history remains available. Fresh queue capability proof is a read-only list, never resume/create/start. For this slice only reviewed0.161 queue mutations are allowed; this is a per-operation compatibility constraint, not the permanent general version-lock solution. Existing0.160 history/directsend continues unchanged.

Read endpoint returns queue object. Enqueue endpoint body project,sid,message_id,text,optional selection; cancel body project,sid,queued_submission_id,action_id; strict unknown-field refusal. Success/error/auth status follow current chat endpoints. No new response text in raw logs. Separate native queue payload lives in vendor's preexisting local state; Control enqueue receipts remain digest-only, cancel action receipts digest-only. Transfer private text extension deferred with INV-SQUEUE-06.

UI defaults composer to queue when supported, with labelled direct-send mode to preserve explicit model/effort functionality. Queue mode shows inherits-at-dispatch explanation and prevents explicit override submission; switching to direct is explicit. Unsupported vendors continue direct send with visible queue-unavailable explanation. Local sending bubble appears immediately; native queue bubbles restore after reload and refresh/SSE invalidation. Cancel action reflects honest native result. No busy Send now button except disabled explanation while transfer decision pending.

## Independent DESIGN clarifications 10.10
Control durable receipt is digest-only enqueue/action intent, never a second pending payload/dispatch store. Native remains sole queue authority. Existing send_status(project,sid,message_id) and GET /api/session-send-status are extended to queue receipt schema: replay/status reads reconcile queued/unknown through validated native queue clientID+payload digest and authoritative history clientID evidence. A queue-listed match proves queued; history match proves accepted and outranks queued; otherwise retain current queued or delivery_unknown, never infer cancellation/delivery failure from absence, even on complete list. No automatic repeat/add. If ambiguous multiple matching native rows appear, report delivery_unknown/conflict and do not mutate/dedup/delete them. The receipt field queued_submission_id is an opaque native ID; queued and accepted return shapes remain distinct.

Proof precedence: accepted history > exact queue match > enqueue ACK > unknown. No async queued ACK may downgrade accepted bubble/receipt. Draft can clear upon ACK or exact queue/history proof of the same admitted immutable UUID+payload, never on unknown or mere absence. Matching history clientID alone is used only when it can be tied to the immutable receipt and native authoritative entry; a mismatched payload under same clientID is conflict.

Partial listing permits item-specific cancel for each visible valid row; missing entries never prove absence. Cancel is intentionally by ID independent of edits, applies equally to native Mac rows without a Control enqueue receipt, and has its own durable action UUID+target digest reservation. UI explains cancellation applies to that item even if it was edited elsewhere. API cannot return the deleted version/text digest, therefore it must not fabricate which version was deleted. Repeated action UUID is replayed from its own receipt, not coupled to the original row's UUID provenance.

Override rejection is server-side before any native add, regardless of crafted client mode. Queue-specific methods are added to fixed native allowlist individually, and each mutation requires fresh native0.161 operation/context proof; other versions give explicit unsupported_queue while history/directsend retain their existing behavior. Missing/unsupported queue methods do not trigger resume/config edits or fallback turn/start.

Frozen core has NO /api/session-queue-send-now mutation route. Expose send_now_supported=false and reason until the pending product decision yields a separate transfer amendment and independent RED. INV-SQUEUE-06 and its proposed endpoint are design-only; private recovery payload storage/retention is deferred too, not an implementation requirement of this core. No local pending text is stored by core. Native queue persists its existing text. Add source/HTTP/status tests for Mac-originated cancel, unknown add/history precedence, and partial-list visible-row cancellation.
