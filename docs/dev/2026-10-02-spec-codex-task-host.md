# CXTASK-HOST: owned dedicated App Server supervisor

Дата: 2026-10-02. Родитель: CONTROL-CXTASK-HOST; решение владельца: отдельный task App Server, inherited defaults, без нового аккаунта. Домен: docs/specs/codex-sessions.md, дополнение INV-CXHOST-01..05.

## Проблема и результат

Policy и transport helpers не владеют процессом. Runtime получает Linux supervisor одного отдельного App Server на одну task incarnation. Systemd user transient service с KillMode=control-group содержит server и его потомков; имя unit генерируется один раз и сохраняется до запуска. Supervisor не запускает turn и не принимает readiness за допуск task capabilities. Модель, effort, пользовательский config и общий daemon не меняются.

Журнал вне worktree durable до каждого неоднозначного эффекта; start никогда не повторяется по уже записанному intent. При crash/timeout повторное открытие читает тот же journal и только сверяет unit. Стартовавший unit идентифицируется уникальным именем, Description ownership token, KillMode и InvocationID. Иной InvocationID/description/режим, отсутствие прежде running unit или ошибка manager дают unknown и не разрешают stop/restart. Pending start может быть принят лишь по точному token/режиму и активному unit с непустым InvocationID. Recovery не присоединяется к native thread и не разрешает cleanup worktree.

Stop выполняется только при явном quiescent=True от доверенного runtime, который ранее доказал отсутствие активных native turns и tool effects. Ложь caller здесь не исправляется: это контракт orchestration boundary. Stop intent записывается до manager.stop; успех подтверждается выходом pinned original MainPID и drain pinned original cgroup; stop по unit name запрещён (см. уточнение после review). Deadline timeout оставляет stopping, recovery допускает stopped только при matching invocation + inactive/failed, MainPID=0 и пустой ControlGroup. Missing unit после неизвестного результата — unknown; missing unit после durable stopped receipt сохраняет stopped. Ни unlink socket, ни rm journal/worktree, ни reset-failed/shared-daemon operations не выполняются. Автоматического рестарта нет: новый generation допускается отдельным orchestration решением после quiescence, за пределами этой фичи.

## Размены и ограничения

Linux systemd user обязателен; отсутствие manager запрещает launch без fallback. Перезапуск означает recovery existing invocation, не повторный start. Local filesystem locks не являются fencing против злонамеренного клиента того же uid. Default config/auth inherited не доказывает capability isolation: admission policy и дальнейшее native подтверждение обязательны до turn/start. Socket inode не доказывает native protocol identity и не является permissions attestation. Операции очистки не входят. Trusted dynamic bridge, approvals routing, registry/reconciler/UI wiring и production deployment идут следующими этапами.

## Native уточнение 0.160.0: Unix socket alias

Native эксперимент показал unix://PATH как symlink из requested private state directory в absolute canonical socket file под private current-uid directory /tmp/codex-daemon-UID; SO_PEERCRED peer PID оказался native child именно owned unit cgroup. Поэтому arbitrary symlink по-прежнему unknown, но проверяемый native alias разрешается отдельной проверкой. Ни путь с daemon в имени, ни symlink сами по себе не означают shared-daemon ownership.

SystemdTaskManager получает optional peer_probe=None; injectable peer_probe(socket_path:str, *, deadline:float)->dict с pid:positive int, uid:int, cgroup:str. Default probe открывает AF_UNIX stream socket с timeout<=remaining deadline, читает kernel SO_PEERCRED, при ещё открытом socket читает unified cgroup из /proc/peer_pid/cgroup; затем закрывает connection. RPC/initialize/turn не отправляется. malformed/missing/proc read error -> HostError без payload. Peer PID принадлежит returned cgroup; это trusted platform adapter result, не model arguments.

Дополнительный manager method validate_socket_link(socket_path:str, control_group:str, *, deadline:float)->dict: подтверждает absolute canonical parent socket_path (сам socket_path symlink), link текущего uid, absolute target (без промежуточных symlinks и без ..), target Unix socket current uid, direct parent target owned directory без group/world bits. control_group absolute non-root canonical path. Probe confirms peer uid == current uid, valid pid, peer cgroup равна unit group или её subtree (граница '/'). Повторный lstat link/target + readlink после probe обязан совпасть. Возвращает {'link':[dev,ino], 'target_path':canonical_str, 'target':[dev,ino]}. Та же ownership/cgroup проверка нужна при каждом inspect/stop; смена link inode/target path/target inode относительно durable identity -> unknown. Connection разрешён только для peer identity proof, не является capability attestation.

Host socket_identity journal теперь может быть прежним [dev,ino] для direct socket или dict выше для проверенного alias. Для symlink Host вызывает manager.validate_socket_link с current owned status.control_group, validates strict result shape + её link inode against direct lstat. Missing method/error -> unknown. Ordinary file/dangling alias/foreign peer/wrong cgroup/unsafe target directory -> unknown, никогда socket_ready. Existing negative symlink fixture на regular executable остаётся unknown. Default direct-socket behavior unchanged.

Authoritative not-found parser также принимает реальные systemd synthetic fields Description=unit name и KillMode=control-group; пустые тоже допустимы. InvocationID/ControlGroup обязательно пусты, MainPID0, inactive/dead; nonzero show rc допустим только в этом полностью проверенном случае. Иная nonempty Description/KillMode, active/PID/cgroup identity запрещены. Это не stop proof для running/stopping journal.

FR-CXHOST-03/05 дополнительные acceptance: native alias with kernel peer in owned cgroup; reject sibling/foreign/unknown peer and alias/target mutation; adapter injected probe deadlines/redaction. Native no-inference initialize/recovery/scoped stop smoke должен пройти через supervisor. Root первый no-turn native probe scoped stopped через manager после independent token/InvocationID check; supervision отказало symlink, не подключалось к native RPC.

Storage clarification: journal/lock regular files must have exactly one hard link; all state path components remain canonical on every operation, not only constructor. An accidental ancestor symlink or hard-linked mutex cannot be accepted after reopen. Active owned service needs non-root absolute canonical ControlGroup; MainPID alone is not cgroup identity. Invalid syscall/probe/manager data stays payload-free.

Probe addressing clarification: validate_socket_link passes the canonical validated target socket path to peer_probe, not the requested alias. The alias and target metadata are both rechecked afterwards, so a changed pointer cannot be accepted merely because a prior target passed peer proof.

## Уточнение после independent review: stop fencing и argv secrets

Review session 01a0fe1b-6a1c-7f81-a0a5-8cca60e239fd (gpt-6-sol medium) обнаружила unit-name stop TOCTOU. Повторный inspect перед systemctl stop не делает StopUnit invocation-specific. Вместо этого signal направляется только через Linux pidfd pinned original MainPID; systemd завершает original service descendants при main exit. Native эксперимент на установленном systemd255: original main SIGTERM -> unit исчез, pinned original cgroup.events read вернул ENODEV. Unit absence сам по себе не proof; нужны оба anchors.

Дополнение status dict: type='exec', exit_type='main', restart='no', remain_after_exit=False, send_sigkill=True. Active owned admission подтверждает эти поля, остальные значения unknown. Launch явно задаёт --property=ExitType=main, --property=RemainAfterExit=no, --property=SendSIGKILL=yes. inspect CLI properties дополнены Type,ExitType,Restart,RemainAfterExit,SendSIGKILL; loaded responses строго разбирают bool yes/no. not-found synthetic settings не используются как ownership proof, но все ключи обязательны и unique.

SystemdTaskManager(..., process_opener=None) инжектирует trusted opener(main_pid:int, control_group:str, *,deadline:float)->handle. Handle immutable identity attributes pid,uid,cgroup; methods signal(sig:int),exited()->bool,drained()->bool,close(). Default opens pidfd via os.pidfd_open, and original /sys/fs/cgroup/<group>/cgroup.events with O_NOFOLLOW before signal, validates current uid and unified /proc/<pid>/cgroup against exact control_group while anchors open. It never kills by PID number, process group or unit name. exited checks pidfd readiness; drained re-reads captured events FD: populated=0 true, populated=1 false; ENODEV on that already-open original FD means original cgroup removed (requires empty subtree), true. Other errors/malformed data raise HostError. Poll result/handle/proc data strictly typed; no new syscall/command after expired deadline. Anchors close on every path.

manager.stop verifies expected canonical invocation_id32hex, positive main_pid (bool rejected), UUID4 token and unit. Fresh inspect must match exact invocation/main_pid/description token, active/running/non-root cgroup and cleanup fields. Then opens handle, validates handle pid/uid/cgroup and re-inspects same exact status before signal. Replacement before signal -> HostError with no signal. Replacement after final check cannot be affected through old pidfd: old process only, and stop returns unknown when later inspect sees other identity. Sends SIGTERM once to original handle; if still alive after at most1second within deadline, SIGKILL to same handle only. ESRCH is accepted only when handle.exited() confirms old process gone. Poll bounded by supplied deadline (small sleep <=remaining), manager.inspect only. ReturnNone success needs both original handle.exited and handle.drained plus either same-invocation inactive/failed MainPID0 empty ControlGroup, or authoritative not-found AFTER those anchor proofs. Foreign invocation/token/cleanup metadata, unknown/unavailable status, nondrained group, timeout -> HostError (Host returns unknown and preserves stopping). No new unit-name stop fallback. Crash/lost reply with unit absent still unknown on reopen, because anchors are not recoverable from absence. Same-invocation inactive/drained recovery remains supported.

Host.stop passes journal token + snapshot invocation_id/main_pid to manager.stop; durable stopping intent before call; manager None return is trusted drain attestation and records stopped. Tests fake manager adopts extended kwargs and certifies own synthetic drain. Quiescent caller gate remains mandatory. Failed/timeout stop receipt never fabricated.

Secrets: systemd-run argv uses --setenv=NAME only, inheriting present values from invoking environment; proxy credentials/config values never appear in argv, journal or errors. No env values copied into literal ExecStart. Public interfaces never receive secret values in test/report output.

FR-CXHOST-04/05 additional independent tests: replacement before handle signal, replacement during signal, original main exit but group populated, authoritative absence without anchor proof, closed handle on all paths, deadline/escalation to exact same handle only, missing pidfd support fail closed, inherited proxy URL absent from all argv; original syscall fake manager may not use unit-name stop.
