# Native evidence fixture contract for naming migration

This reference describes existing public fixture APIs. Admission and bootstrap proof relocation is currently unsupported; naming preflight must refuse before moving any root when either retained artifact exists. The refusal preserves all bytes, permissions, operation identities, and provider history. An operation-store thread ID by itself is not evidence of a retained native admission: closed standalone store fixtures remain supported.

The admission location is `STATE_ROOT/STATE_ID/admission.json`, where STATE_ID comes from the validated operation-store snapshot. A bootstrap proof location is `Path(operation['host_state_dir']).parent / 'bootstrap-proof.json'`; discover it from authoritative operation identities, not an assumed operation directory name. Also refuse an unbound bootstrap proof in the state directory rather than silently carrying it forward. Existence includes malformed files or unexpected directories: no schema error may become permission to move.

For a provider-generated valid baseline use `RuntimeContract` in `tests/test-codex-task-runtime.py`: its existing `test_drained_bootstrap_publication_crash_repairs_only_from_exact_durable_proof` calls `publish_registry()`, `discovery_fixture(native_mode='read', bootstrap_publication_fault=True)`, and `controller.execute('event-1', 7, 'attempt-1', deadline=...)`. All hosts are stopped; the provider fixture produces a valid proof. After removing the deliberately injected admission directory, `controller.reconcile(deadline=...)` reconstructs the admission exactly from that proof without additional model calls. This is the authoritative valid admission/proof fixture; tests should retain its successful recovery assertions before checking migration refusal.

Admission fields are exactly incarnation, release, tools, mcp_names, thread_id, thread_path, model, reasoning_effort, permission_profile, config_digest, registry. Proof schema1 fields are schema, operation, admission, terminal. Existing runtime validators check release hashes, dynamic tools, sealed policy digest, registry membership, exact thread/turn/operation/incarnation identities, terminal quiescence, and native provider metadata. Do not invent weaker JSON that bypasses these validators.

`read_thread_metadata` reads the first immutable provider session_meta line and requires its cwd and roots to match the bound runtime cwd. Bootstrap registry recovery additionally validates historical turn_context cwd. Changing only admission.config_digest cannot rebind those records. Provider session history must remain untouched.

A future supported relocation contract would retain an owner-private, exact-thread migration proof binding original session_meta bytes/fingerprint, provider path and identity, original cwd/roots and canonical cwd. It must validate the original sealed admission digest, preserve operation identities, separately validate historical bootstrap turns against their original cwd, and prove canonical sealed thread/resume responses before permitting new execution. That extension is not implemented by the naming helper and must have independent recovery/resume tests before activation. Actual target inventory decides whether this unsupported-state barrier blocks rollout; a local empty inventory does not establish target emptiness.

Lifecycle native identity records under Path(operation.host_state_dir).parent/lifecycle also bind cwd/thread. Presence of retained lifecycle records is an unsupported-state preflight barrier before any root move; include count-only inventory and malformed/unbound records. Empty directories alone contain no retained identity.
