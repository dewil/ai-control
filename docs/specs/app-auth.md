# Общая авторизация приложений

Принятые решения от 07.10.2026: общий API для Android/iOS, username/password/TOTP и постоянный допуск устройства. Существующий web R5 сохраняется. Сейчас поддерживается один настроенный владелец; multiuser требует отдельного изменения. Авторизация устройства и аккаунта провайдера относятся к разным доменам.

- INV-APP-01: `POST /api/app/login` принимает JSON с точным набором полей `username`, `password`, `totp`. Используются тот же verifier владельца, rate limiter и TOTP replay store, что у `/api/login`. Username чувствителен к регистру и требует ASCII fullmatch `[a-z][a-z0-9_-]{1,31}` (без якоря `$`, допускающего trailing newline). Неверный формат дает 422; допустимое, но неверное имя, пароль или TOTP дают одинаковый 401. Неизвестное имя требует password hash work, но не потребляет TOTP и не создает device grant. Principal, role, account и client platform из запроса не управляют полномочиями.
- INV-APP-02: `POST /api/app/session` принимает только `foreground_open` типа boolean и единственный `Authorization: Bearer <device_token>`. Cookie WebView остается Secure/HttpOnly/SameSite Strict со сроком 3 часа. Приложение восстанавливает сессию через grant, без хранения пароля/TOTP. Origin точно совпадает с настроенным HTTPS origin. Отсутствующий, повторный или некорректный auth не может дать успех.
- INV-APP-03: `POST /api/app/logout` принимает `{}` и Bearer capability, отзывает соответствующий grant. Последующий допуск и cookies, связанные с этим grant, отклоняются. Существующие lifecycle fences web logout и native bridge сохраняются; grant автоматически не перевыпускается. Токены, cookies, пароль и TOTP не попадают в URL, логи, backup, обычные preferences или публичный каталог.
- INV-APP-04: Политика устройства сохраняется: idle 7 дней, срок grant 30 дней; только успешное явное foreground open обновляет last_open и expires=now+30 дней; фоновые события и foreground_open=false их не меняют. Это rolling 30-day deadline, не фиксированный lifetime от первого входа. Границы отказа включительные: now-last_open>=7 дней или now>=expires. Сервер хранит SHA-дайджесты токенов в private SQLite, native encrypted store хранит capability. Перезапуск процесса не стирает grant. Неизвестный, отозванный или просроченный grant отклоняется. До интеграции пользователей/grants допускается один владелец, без автоматически выведенных user/provider bindings.
- INV-APP-05: Публичный namespace всех native платформ - `/api/app/`. Старые `/api/android/login`, `/api/android/session`, `/api/android/logout` не публикуются как aliases: старый APK не имел работающего серверного endpoint. Web `POST /api/login`, `GET /api/session`, `POST /api/logout` сохраняются, без переноса на `/web/login`. `/download/android/` остается каналом APK; доставка iOS отдельная.
- INV-APP-06: Native форма содержит редактируемый username перед password/TOTP, с подсказкой login. Имя передается точно как введено, без trim, casefold или hardcoded owner. Пароль и TOTP очищаются после отправки. Сохраняются callback, generation, foreground, redirect и TLS fences. Универсальный JS bridge и переопределение сетевых endpoints не добавляются.
- INV-APP-07: Интеграция начинается с принятого R5 `0ea5447`. Сохраняются username владельца `dwl`, настроенные пароль/TOTP, replay, `session_ttl=10800`, chat/history/cloud и footer CSS. Android modules/assets/contracts из `fadbfe6` переносятся выборочно; legacy web дерево не заменяет R5. Изменять обязательные services/dependencies можно только после отдельного обоснованного review.
- INV-APP-08: APK `0.1.2`, code `3`, package `ru.dewil.aicontrol`, min SDK 26, target SDK 36 использует прежний release certificate `baa20956801a031fd5acd36d9c11438f49fd04ef07304eaf99fb9853575888ce`. Проверяются точные hash/package/code/signer APK. Секрет подписи не попадает в репозиторий, артефакты или логи. Versioned APK неизменяем; APK публикуется до атомарного обновления manifest. Публичные landing/feed используют no-store, APK - immutable; в панели остается постоянная ссылка скачивания.
- INV-APP-09: Новые server helpers требуют отдельного проверенного bootstrap фиксированного scope с 14 до 16, с прежним signing trust, sudo без произвольных аргументов, постоянным журналом и rollback. Config/grants не входят в payload. Auth и native runtime провайдеров сохраняются. Компиляция instrumented tests не доказывает production/release acceptance.

Traceability: независимые HTTP/auth/device/restart/logout/rate/TOTP tests и проверки публичных landing/cache/manifest; Android payload/field/version tests, существующие policy/updater checks и компиляция native tests; полный web/naming/install/deploy CI; доказательства signed package и установленного HTTPS release. Вход на устройстве пользователя и обновление N->N+1 проверяются отдельно.

Точная API-матрица, JSON/token/Bearer validation order и shared limiter/replay semantics зафиксированы в `docs/dev/2026-10-07-spec-app-auth-release.md`, раздел "Точная матрица API и порядок проверок". Exact16 bootstrap обязателен до публикации; scope14 не допускает app release.

Известные ограничения: до проверенной server integration `/api/app/` отсутствует. Instrumented tests на устройстве и системное обновление имеют статус NOT RUN до фактического исполнения.

INV-APP-03/04/06 включают нормативный запрет mutation replay и generation fences из раздела "Native recovery и независимый RED" активной feature spec. Draft INV-AND-01/02 закрыты этим контрактом, но результаты исполнения требуют отдельной приемки.
