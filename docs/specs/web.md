# Веб-интерфейс Control

## Границы и решения
04.10.2026 пользователь поднял веб до P1 и выбрал управление задачами: ответы на вопросы и принятие результатов. Панель на llm; отдельный непривилегированный пользователь; password+TOTP и cookie. Исторический read-only MVP заменён полезным task workflow. Первый task выпуск завершён; сессии развиваются отдельным следующим контрактом web-sessions.md. Запуск задач, отмена, поиск, diff и лимиты вне первого task выпуска. Без БД и внешнего identity provider.

## Инварианты
- INV-WEB-01: Неаутентифицированный посетитель не получает данные задач и не вызывает writers. Вход требует пароль и TOTP; пароль хранится scrypt hash, TOTP secret в приватном файле вне репозитория, никто не печатает секреты. Повтор использованного TOTP шага отклоняется; rate limit ограничивает перебор.
- INV-WEB-02: Сессия случайная, ограниченная по времени, cookie HttpOnly, Secure, SameSite=Strict; logout отзывает её. POST требуют привязанного к сессии CSRF token и точного Origin; GET ничего не меняет. HTTP допустим только explicit loopback development с выключенным Secure, production только за HTTPS и exact configured origin; proxy headers не расширяют доверие.
- INV-WEB-03: Web-user не читает OAuth, не пишет реестр. Owner broker через private Unix socket проверяет SO_PEERCRED UID; только фиксированные snapshot/answer/verdict команды и session operations из web-sessions.md. Нельзя передать путь, shell, executable, env, cancel или произвольный argv. Не доверять полям клиента и agent content.
- INV-WEB-04: Ответы исполняет ai-agent-answer, вердикты ai-agent-run done-verdict. Существующие неизменность первого решения, locking, recovery, native authorization и drain barriers сохраняются. Устаревшая карточка не принимает новую заявку; generation hash = sha256('done-gen:'+envelope_key+':'+commit_sha)[:8]. UI не считает transient, stale и timeout успехом.
- INV-WEB-05: Snapshot содержит allowlist task/name/engine/state/question/result полей, без OAuth, native paths, raw control/config/receipts. Читает только реальный registry child, regular files no symlink, bounded JSON; corrupt record возвращает видимую недоступность без раскрытия stderr/секретов. Agent names ограничены safe basename, qid canonical UUID, generation 8 lowercase hex. Строки недоверенны и отображаются textContent/escaped HTML.
- INV-WEB-06: Info вопрос принимает непустой текст до 16000 символов. Permission принимает только approve/reject, а Codex только advertised allowed decisions с canonical callback; native writer окончательно проверяет актуальность. Закрытые вопросы не показывают active controls. Результат requested/finalized требует явного confirm; reject требует свежий TOTP дополнительно к login. Повтор результата честно сообщает already, stale требует refresh.
- INV-WEB-07: Телефонная страница показывает вопросы первыми и результаты на проверке, task/engine/summary и принятый статус. Есть loading, empty, unavailable, retry, pending mutation, refresh; двойной клик блокируется. Ввод не исчезает при ошибке. Acceptance означает принятие, а не мгновенный merge/deploy. Не включает технические детали в пользовательский workflow.
- INV-WEB-08: Приватные credential/session/runtime файлы mode600/700 вне git и /data; web запускается до unlock и при broker/data outage отдаёт понятную недоступность. systemd sandbox и отдельный UID; публичный адрес/HTTPS/enrollment проверяются перед заявлением готовности.

## Внешний контракт
Python module bin/_control_web.py: create_app(config, backend, clock=None) возвращает ASGI FastAPI app. Config — dict: origin, password_hash, totp_secret, session_ttl (default3600), secure_cookie(defaultTrue); insecure допускается только origin http://127.0.0.1 или localhost с explicit secure_cookie=False. Backend имеет snapshot(), answer(agent,qid,decision,text), verdict(agent,generation,decision,comment); возвращает JSON-safe dict. Hash helpers hash_password(password), verify_password(password,encoded), totp_code(secret,at). Clock callable возвращает epoch seconds. Backend не получает TOTP/password/session.
HTTP: GET / login/UI; POST /api/login JSON password,totp → csrf; cookie control_session. GET /api/tasks → {tasks:[...]}; POST /api/answer JSON agent,qid,decision(text|approve|reject),text; POST /api/verdict JSON agent,generation,decision(accept|reject),comment,confirmed=true,totp при reject; POST /api/logout. Mutations header X-CSRF-Token; login также exact Origin. Errors JSON {error:stable_safe_code}, status401/403/409/422/429/503. Mutation success {status:applied|already}; answer может вернуть saved_pending и HTTP503, не success. snapshot tasks include agent,engine,state,questions[{qid,kind,status,question,allowed_decisions}],result(null или {generation,state,summary,commit_sha,finalized}). Дополнительные безопасные поля допустимы.
Broker module bin/_control_web_broker.py: RegistryBackend(registry,bin_dir,runner=None). Snapshot реализует этот schema. runner callable(args,**kwargs) совместим subprocess.run; argv list shell=False, timeout bounded, sanitized outcomes. answer/verdict вызывают абсолютные trusted bin helpers. Linux socket newline JSON ≤128KiB, one request/connection, peer UID allowlist, strict operation fields. Client SocketBackend(socket_path) реализует backend. CLI bin/ai-control-web: web / broker / init-auth (secret enrollment локально, stdout не содержит секретов; private output file). Systemd templates и отдельная инструкция установки без автоматического public firewall изменения.

### Registry и ошибки (уточнение контракта до RED)
Registry root содержит <agent>/spec.yaml (JSON является допустимым YAML; type: task, engine: claude|codex, name), control.json (generation), state.<generation>.json (phase/status_line), questions/<qid>.json ({qid,kind:info|permission,status:open|closed,question,envelope_key,asked_at,engine?,native_callback?}), done.json ({state,finalized,envelope_key,commit_sha,summary}). Snapshot включает только type=task. Состояние берётся из state.phase либо unknown. Для простого permission разрешены approve/reject, native callback allowed_decisions строго [reject] либо [approve,reject] отображаются без расширения; writer остаётся finalauthority. Повреждение spec/control/questions/done видимо через task unavailable=true; absence optional questions/done допустим. Ограничение одного файла128KiB, одного поля16000 chars, максимум1000 tasks/questions; превышение даёт unavailable, не silently empty.
answer argv: [<bin>/ai-agent-answer,<registry>/<agent>,--qid,<qid>,--text,<text>|--approve|--reject,--by,web]. rc0 → {status:applied}; rc1/rc2 → {error:invalid_or_stale}, rc7 → {error:saved_pending}; прочее/timeout → {error:unavailable}. verdict argv: [<bin>/ai-agent-run,done-verdict,<registry>/<agent>,--accept|--reject,--expect-sha,<generation>,optional --comment,<comment>]. rc0 stdout applied|already → status; rc3 → error stale; rc1/timeout → unavailable, rc2 → invalid_or_stale. Backend errors are dict error; HTTP maps stale/invalid_or_stale409, saved_pending/unavailable503; rejects malformed HTTP422 before backend. Public server helper serve_broker(socket_path,backend,allowed_uid,stop_event=None): blocking Unix socket server; optional threading.Event terminates idle server within1s; active trusted writer may finish within its bounded60s deadline before shutdown. Wire request {op:snapshot} / {op:answer,agent,qid,decision,text} / {op:verdict,agent,generation,decision,comment}; unknown/extra fields refused, unauthorized UID gets safe error and no backend invocation. Socket mode660 in private parent, never replace pre-existing non-socket or another-owner path.

### Replay и HTTP limits (уточнение перед security review)
create_app config может содержать totp_state_path — private regular file c JSON {last_step:int}. При наличии state хранит consumed TOTP step durable до успешного login/reject; второй create_app/restart с тем же файлом не принимает уже использованный шаг, unreadable/corrupt/symlink state отказывает startup без значения в error. Отсутствие опции допустимо только in-memory unit/dev fixtures; production CLI требует этот path и init-auth создаёт state отдельно от immutable auth config. Single-worker упрощает синхронизацию, не отменяет durable replay. HTTP request body ограничен128KiB во время stream чтения, не после полной буферизации; malformed/non-ASCII CSRF отклоняется403 и не вызывает backend.
Registry enumeration совместима с ai-rc agent list: dot-prefixed metadata (штатный .locks), неподходящие NAME_RE имена и nondirectory entries не являются агентами и пропускаются без follow/read. Valid agent-name symlink никогда не читается и может быть обозначен unavailable. Невалидный spec.yaml у valid agent directory виден как unavailable, не исчезает из задач молча. JSON/YAML spec обязан быть object с корректными recognized top-level scalar fields; строка '{' не является допустимым legacy mission spec.

### Уточнения после первого независимого review (04.10)
Allowlist text fields question/name/status_line/result summary/saved answer проходят существующую SECRET_RE/redact policy Control до HTTP; это маскировка известных credential patterns, не обещание определить любой произвольный секрет. Commit SHA может быть null/отсутствовать у workspace none/direct: normalize '' для done-gen, UI не требует Git.
Snapshot question дополнительно имеет answered:bool, pending_delivery:bool, saved_answer:string (redacted), saved_decision:string|null. answered означает durable answered_at != null, pending_delivery — answered и нет event_published_at. Для answered вопроса UI показывает неизменяемый первый ответ/решение, а не новые controls; pending_delivery предоставляет retry original delivery. API и socket answer decision расширен фиксированным 'recover' (text=''); broker вызывает ai-agent-answer --qid <qid> --recover --by web, только recovery сохранённого ответа, не новое решение. При rc0 writer broker перечитывает raw original под safe read: если first value не соответствует request либо уже был сохранён до вызова, status already; для unsaved first matching value status applied. Никакой новый текст не подтверждается, если writer опубликовал прежний. Пока не опубликован — saved_pending, даже если writer outcome неоднозначен. Обычный repeat с новымtext тоже не меняет первого ответа и не сообщаетapplied. UI sorting: unanswered open questions, затем requested/finalized results, затем остальные; saved pending виден как ожидающий доставки.
Production TOTP state обновляется под stable adjacent private lockfile + flock, чтение актуального last_step, проверка кода, durable replace/fsync до session/verdict. Два экземпляра, открывшие один state до входа, не принимают один шаг дважды; файл-state lock по заменяемому inode не обеспечивает это. Отказ записи state не вызывает writer и не выдаёт session.
Canonical Codex callback перед активными controls: nonemptystr attempt_id/thread_id/turn_id/item_id; operation_id canonical UUID; task_incarnation32lowerhex; generation positive plainint (не bool); request_id plainint либо nonemptystr (не bool); method item/fileChange/requestApproval; status pending для нового решения; payload_fingerprint/changes_digest64lowerhex; allowed_decisions ровно [reject] либо [approve,reject]. Corrupt callback => unavailable или noactivecontrols, не синтетическое permissiongrant. Writer дополнительно проверяет актуальность authority. Уже сохранённый answer с callback answered отображается readonly/recovery, не новымapprove. Старый blindfixture с одним allowed_decisions уточняется originaltestwriter до полного canonical fixture, без ослабления assertions.
Known-pattern masking включает весь установленный SECRET_RE экспортирующего ai-agent-run: api_key/api-key, access_key/access-key, token, secret, password, passwd, pwd, authorization, bearer и существующие token/long-string forms. Нельзя брать более узкий Telegram subset и пропускать short access_key/passwd/pwd значения. Политика одинакова для всех allowlist text fields и saved answer.

## Восстановление сессии при reload (04.10.2026)

INV-WEB-11: GET /api/session возвращает существующий CSRF по действующей HttpOnly cookie, без создания сессии, продления TTL, TOTP или backend calls. Отсутствующая/истёкшая/отозванная cookie получает401, чужой explicit Origin —403; ответы no-store. UI bootstrap скрывает login до проверки, восстанавливает workspace и mutation CSRF либо показывает login после401. Transient failure оставляет retry восстановления без credentials; browser storage не используется. Traceability: tests/test_control_web_session_reload.py и synthetic browser reload/logout/retry.


## Пользователи и project grants (05.10.2026)
INV-WEB-12: В явно включённом multiuser режиме administrator только один — owner. Delegate view/answer/verdict/recover разрешены только явным project grants, привязанным к authoritative alias/root; empty/missing/disabled/malformed не дают доступ. Не доверять project/principal/grants из HTTP body или task content. Проверять policy и project на защищённой writer границе до side effects, включая barrier; фильтрация UI не является контролем доступа. Корни реализации: docs/dev/2026-10-05-spec-web-project-users.md.

Известная дыра multiuser: текущий owner-only contract не имеет per-user policy/authentication/project filtering и writer fence guards. Multiuser нельзя включать до закрытия всех корней; первый policy-only корень сам по себе доступов не выдаёт.

Трассируемость policy-only части INV-WEB-12: tests/test_control_web_access_policy.py (21 independent methods; owner-bypass и same-root/wrong-alias sensitivity controls). Брокерная/writer/auth часть остаётся известной дырой до следующих корней.
