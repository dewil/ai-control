CLI провайдеров claude/codex, их OAuth/config dirs .claude/.codex и model ids не переименовывать.

## Инварианты
INV-NAME-01: canonical исполняемые имена bin/claude-control*→ai-control*, bin/claude-agent*→ai-agent*, bin/claude-rc*→ai-rc*. Codex CLI/voice-report/helpers остаются. Internal references, templates, manifest, CI/test fixtures используют новые имена; старые wrapper/symlink aliases не устанавливаются. Регрессии существующих алгоритмов сохраняются, mechanical fixture updates допускаются с указанием причины.
INV-NAME-02: product paths ~/.claude-control→~/.ai-control, ~/.config/claude-control→~/.config/ai-control, ~/.local/share/claude-control→~/.local/share/ai-control, /opt/claude-control-web→/opt/ai-control-web, /var/lib/claude-control-web→/var/lib/ai-control-web, /run/claude-control-web→/run/ai-control-web. User/system systemd and launchd labels/templates получают ai-control/ai-agent имена. Web isolated account/group ai-panel (перенос владения выполняется root этапом до enrollment). RuntimeDirectory/ReadWritePaths/socket/Host+Origin порт согласованы. ccsession-* transient identity не меняется, чтобы не потерять ownership proofs действующих записей.
INV-NAME-03: env public namespace CLAUDE_CONTROL_*→AI_CONTROL_*, CLAUDE_RC_*→AI_RC_*, CLAUDE_AGENTS_DIR→AI_AGENTS_DIR. Другие CLAUDE_* сохраняются как provider contract или отдельно инвентаризируются; не blind-replace provider vars. env files содержимое секретов никогда не выводится; migration обновляет только точные product path/command/env keys внутри trusted config, не task user text/spec/model ids.
INV-NAME-04: offline migration ai-control-migrate-names сначала preflight всего набора, затем move данных с preservation bytes/modes и локальным receipt без секретов. Registry/questions/spool/lessons/projects/history и web auth/TOTP-state не сбрасываются. Если destination существует параллельно source, symlink source/target, active runtime или unsupported cross-device move — отказ до mutation, никакого merge/overwrite. Повтор после завершения no-op. Dry-run не изменяет files/dirs/units. По отдельным unrelated provider dirs не ходит.
INV-NAME-05: migrate user helper CLI контракт `ai-control-migrate-names --home PATH [--dry-run]`, работает только user-owned private dirs, не меняет root dirs/units/SSH/firewall. До moves проверяет systemctl --user список активных claude-control*/claude-agent*/ai-control*/ai-agent*/ccsession-* and cctask-* services; доступный user manager обязателен для apply. Root web migration отдельным конкретным runbook: frontend/broker stop+disable, проверить отсутствие enrollment либо locally move auth+state с ownership/mode preservation, новый package из immutable SHA, ai-panel, newunits/proxy config проверяются до start. Старый пакет не masquerade через symlink и не enable oldunits совместно. Root install после accepted code и независимой сверки.
INV-NAME-06: действующие TASK data не переписываются blind заменой строк. Перед rollout остановить runtime services, проверить/дождаться отсутствия активных ccsession/task host processes; если нельзя остановить безопасно, deployment blocked, код может быть принят. Registry references к old worktrees/bin в authoritative execution metadata требуют inventory и явного переноса trusted keys отдельно; пользовательские тексты не заменять. Установка новых commands не заменяет доказательства безопасной миграции и public phone acceptance.

### Уточнение публичного migration contract
Exact user roots: --home/.claude-control → --home/.ai-control; --home/.config/claude-control → --home/.config/ai-control; --home/.local/share/claude-control → --home/.local/share/ai-control. Registry/spool/lessons/projects/history сохраняются как произвольное содержимое первого root; provider dirs .claude/.codex не входят. Receipt хранится в --home/.ai-control/naming-migration.json (mode600, новый файл, если source absent и все target absent, no-op без создания). Receipt минимально содержит version=1, migrated_roots список относительных новых путей; никаких содержимых/секретов. Existing receipt не перезаписывается, повтор completed migration no-op. Ни один move не выполняется до preflight всех корней. Canonical installed список получается из baseline scripts.manifest при точных basename replacements и добавлении ai-control-migrate-names; backup optional scripts также canonical rename. Template basenames меняются теми же replacements. systemctl manager failure apply отказ, dry-run may report unavailable manager but must not move.

### Product env и stopped TASK metadata
Product prefix map: CLAUDE_CONTROL_, CLAUDE_RC_, CLAUDE_AGENTS_, CLAUDE_AGENT_, CLAUDE_RECONCILER_, CLAUDE_TGBOT_, CLAUDE_HARVEST_, CLAUDE_EVENT_ → соответствующие AI_*; exact CLAUDE_BACKUP_ENV→AI_BACKUP_ENV. CLAUDE_BIN/CLAUDE_CONFIG_DIR и provider usage/creds selectors остаются. Legacy obsolete cleanup claude-agent-commit и retired claude-agent-canon-maintainer сохраняют старые имена как намеренно удаляемый исторический artifact, не canonical entry.

Перенос stopped TASK metadata: opaque task/user files сохраняются byte-for-byte; authoritative runtime index.json host_state_dir и drain/terminal evidence path fields, directory-identity.json directories keys, stopped host journal cwd/socket/target_path и executable под product-owned prefixes требуют точной schema-aware relocation из source prefix в destination, с сохранением dev/inode identity (same-device rename). Любой неизвестный schema/nonstopped journal/socket live/невозможность безопасно validate→refuse before first move. Не менять token/uuid/generation/attempt/ownership proofs, task text/spec/context, provider paths. Stage все metadata updates до moves; приватные rollback copies/receipt не содержат stdout; при failure сохранять recovery evidence, не заявлять completed. Проверка relocated store существующим authoritative validator на synthetic stopped operation обязательна, одного string replacement недостаточно. Root/operator migration живых task сначала drain/stopped proof, no hot migration. Если реализация не может гарантировать metadata relocation, report blocker до GO, не выдавать отказ навсегда за выполненную full migration.

Task host cctask-* также блокирует offline apply; отсутствие active ccsession недостаточно. Registered git worktrees требуют отдельного operator git worktree repair/verification после остановки задач и переноса каталога; helper не изменяет внешние git metadata молча. Для обнаруженного неподдерживаемого registered worktree — preflight refusal и конкретный операторский шаг, не успешный receipt.

Offline manager inventory включает active product service И timer units: timers могут начать запись после service inactivity. Query list-units без type ограничения либо включает оба types; активный claude-control*/claude-agent*/ai-control*/ai-agent* timer также требует отказа перед mutation.

### Durable transaction checkpoint
До первого move или metadata update helper создаёт --home/.ai-control-naming-transaction owner-only700: plan.json600 schema/version1 с whitelist pairs roots и относительными backup references, originals private600 с исходными metadata bytes (не выводить). Plan/backup files и checkpoint directory fsync before first move. Checkpoint не находится внутри moving roots. Успешная миграция/проверенный rollback удаляет checkpoint; process interruption или failure восстановления сохраняет его. Existing checkpoint блокирует новую apply/dry-run до reviewed local recovery, никаких автоматических overwrite/merge. Runbook описывает восстановление metadata/roots по exact trusted plan после stop/drain, отказ unknown layout/modifiedstate и сохранение checkpoint до authoritative/Git validation; CLI --recover не обязателен. Риск процесса между rename и recording учитывается inventory фактических source/destination, не blind reverse counts. Test contract: interruption after first rename leaves checkpointprivate+durable originals и повтор refuses/inert; injected metadata write failure restores root/schema and either verifiedcleanrollback/nocheckpoint or retainedcheckpoint if rollback fails.
