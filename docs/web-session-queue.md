# Очередь сообщений и совместимость Codex

Контракт веб-панели r12. Фактически установленная версия и время сборки указаны внизу панели; обновление веба не требует нового APK.

## Отправка

Для поддерживаемой сессии Codex по умолчанию выбран режим «В очередь». Сообщение сразу появляется в чате, затем штатная очередь Codex запускает его после текущего хода. В свободной загруженной сессии запуск может начаться сразу. Порядок, хранение и автоматическое продвижение принадлежат Codex; закрытие телефона не останавливает очередь. После перезагрузки панель перечитывает её с сервера, включая сообщения из клиента на Mac.

Штатный API очереди не принимает отдельную модель или уровень размышления: применяются настройки сессии на момент запуска. Для явного выбора модели используйте режим немедленной отправки. Панель не должна молча отбрасывать выбранные настройки.

«Отменить» удаляет ещё ожидающий элемент. Если Codex уже забрал его в работу, отмена не подтверждается; это не остановка текущего хода. Подтверждённая отмена действует на выбранный элемент, включая изменения, внесённые с Mac.

## Отправить сейчас

В работающей сессии можно выбрать «Отправить сейчас». Панель показывает снимок текста и предупреждает, что одновременные изменения на Mac могут не попасть в отправку. Подтверждение отправляет именно показанный снимок.

Сервер сохраняет данные для восстановления, подтверждает удаление из штатной очереди и повторно проверяет выбранный активный ход. Вмешательство направлено только в этот ход. Если он успел завершиться до передачи, текст остаётся в разделе восстановления; в другой ход он автоматически не отправляется.

«В черновик» только копирует сохранённый текст. Новая отправка требует отдельного нажатия и нового идентификатора. Неоднозначный результат передачи показывается как «Доставка неизвестна»: автоматический повтор отключён, доступна ручная проверка. «Принято» означает приём входа Codex, а не завершение работы или немедленное потребление текста. Сообщение в текущий ход само по себе не подтверждает права на команду: native approval принимается отдельно.

## Совместимость

Нативная очередь проверена по API Codex0.161 и использует экспериментальные thread/queue методы. Включение экспериментального API не даёт разрешения на произвольные RPC: панель использует фиксированные проверенные операции и сохраняет проверки владельца, проекта, thread и поколения соединения.

Совместимый новый номер версии сам по себе не отключает список проектов, сессий и историю. Ответы проверяются по структуре и области доступа. Непроверенные команды отключаются отдельно; интерфейс показывает версию и причину ограничения.

После явного прерывания хода штатная очередь может остаться приостановленной. В этом срезе продолжение возможно через родной клиент или новый явный немедленный ход; отдельное управление запуском приостановленной очереди вынесено в backlog. Очереди других вендоров требуют своего адаптера, их готовность этим выпуском не заявляется.

## Хранение и пределы

Обычные Control подтверждения содержат digest и идентификаторы; очередь и её тексты хранятся в Codex. Снимок незавершённого переноса хранится отдельно как приватная recovery-запись внутри owner receipt storage, вне Git и синхронизируемых каталогов, с ограничениями размера и доступа. После терминального разрешения текст удаляется, защита от повторного выполнения сохраняется.

Control не повторяет неоднозначные команды. Это не обещание exactly-once для самого Codex при аварии: в его реализации запуск хода и удаление строки очереди — отдельные действия. Авторизация вендора и привязка аккаунтов этим срезом не меняются.
